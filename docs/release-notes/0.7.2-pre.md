# satd 0.7.2

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

A bug-fix release for 0.7.1. No reindex.

## Highlights

- **A fresh testnet4 sync gets past block 51,540.** In 0.7.0 and 0.7.1 it
  stopped there for good ([details](#ibd)).

## IBD

A fresh testnet4 sync on 0.7.0 or 0.7.1 stopped at height 51,539 and never
got further (#1216). Block 51,540 holds ten transactions of 1,420 inputs
each. The script engine re-reads the whole transaction for every input, so
checking that block takes minutes on a busy machine, while connecting no
block and blocking the P2P loop. After 300 s the stall watchdog took that
for a wedge and shut the node down, and every restart came back to the same
block.

Two changes, either of which gets the sync through:

- **Default `-assumevalid` for testnet4 and testnet3.** They now ship
  Bitcoin Core's defaults: testnet4 block 123,613
  (`0000000002368b1e4ee27e2e85676ae6f9f9e69579b29093e9a82c170bf7cf8a`) and
  testnet3 block 4,842,348
  (`000000007a61e4230b28ac5cb6b5e5a0130de37ac1faf2f8987d2fa6505b67f4`).
  Before, neither had a default, so every script was verified. Scripts are
  skipped only under Core's conditions, as for mainnet and signet. Mainnet
  and signet keep their defaults. `-assumevalid=0` still verifies
  everything.
- **The stall watchdog counts script verification as progress.** Script
  inputs verified now reset its timer, as a connected block or a turn of
  the P2P loop already did. A block that takes minutes to verify no longer
  triggers it. A real wedge still does: when nothing is verified, nothing
  connects and the P2P loop is stuck, the watchdog fires after
  `-stallwatchdogsecs` as before.

## Upgrade notes

No action required; a drop-in upgrade from 0.7.1. A testnet4 or testnet3
node already past the default block keeps running as before. A node stuck
at 51,539 on 0.7.1 continues its sync after the upgrade.

## About this release

satd is free software under the [MIT License](../../LICENSE).

- **Stability & compatibility** — Tier 1 surfaces (Bitcoin Core-compatible
  JSON-RPC wire shape, CLI flag names/defaults, `bitcoin.conf` keys, on-disk
  layout, Electrum/Esplora surfaces) are governed by
  [`STABILITY_POLICY.md`](../../STABILITY_POLICY.md). satd follows
  [semantic versioning](https://semver.org/spec/v2.0.0.html): each feature
  release raises the minor version, and deprecations may be accelerated (see
  the policy).
- **Security & disclosure** — report vulnerabilities per
  [`SECURITY.md`](../../SECURITY.md). Consensus-affecting bugs are treated as
  P0 with same-day acknowledgement.
- **Verifying this release** — tarballs are signed with minisign, container
  images with cosign (keyless OIDC), and git tags with SSH signatures (no GPG).
  The key matrix and verification steps are in
  [`SECURITY.md`](../../SECURITY.md).
- **Intentional differences from Bitcoin Core** — catalogued in
  [`CORE_DIFFERENCES.md`](../../CORE_DIFFERENCES.md).
- **Operating satd** — observability, the full flag matrix, tuning, and the
  downstream packaging contract live in the
  [Operator Manual](https://epochbtc.github.io/satd/).
