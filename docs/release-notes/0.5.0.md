# satd 0.5.0

> Released 2026-08-25 · git tag [`v0.5.0`](https://github.com/epochbtc/satd/releases/tag/v0.5.0) · [Changelog](../../CHANGELOG.md)

satd 0.5.0 is the **wallet-backend release**, headlined by BIP 352 silent
payments — receive-side and end to end. Alongside it: a first-party **Go SDK**
(`satdevents`), **node health alerting** across three surfaces, three BIP 141
witness rules brought to exact Core parity, and a set of chain-integrity fixes
proven under sustained production use. Defaults stay Bitcoin Core-compatible,
and silent payments are off unless you turn them on.

## Highlights

- **Silent payments (BIP 352).** A node-side tweak index, a streaming tweak
  firehose with taproot-era cold-sync, mempool-time detection, and an optional
  server-side scan-key matcher. All opt-in (`silentpaymentindex=1`, default
  off), validated against the BIP 352 v1.1.0 test vectors.
- **A first-party Go SDK** — `satdevents` at `clients/go/`, in full parity with
  `satd-events-client` and held there by a differential harness that diffs both
  clients' view of the same node, event for event, on every PR.
- **Node health alerting** — six detectors reported simultaneously as streaming
  `status` events, `getwarnings` entries, and Prometheus gauges, plus signed
  `alertfile` webhooks.
- **Three BIP 141 witness rules brought to exact Core parity** — satd accepted
  blocks Bitcoin Core rejects. Not reachable through honest mining, but each was
  a chain split with satd on the losing side.
- **The chain tip can no longer stand on blocks that were never connected** — a
  synced mainnet node served a UTXO set missing eight blocks' worth of outputs
  for five and a half hours while reporting a healthy tip.
- **A durability hole between block data and the index that references it is
  closed**, and `getblockfrompeer` can now repair a datadir that already has one.
  Previously a single lost block body meant a full resync.
- **Bitcoin Core v28+ obfuscated block files are readable** — the documented
  "reuse a Core `blocks/` directory" migration now works against modern Core
  datadirs with no configuration.

## Silent Payments

Everything is opt-in and nothing changes for a node that leaves it off.

- **BIP 352 kernel** (`node-sp-index`) shared by the index and the matcher, so a
  tweak the node stores and a tweak a wallet recomputes are identical by
  construction.
- **Tweak index.** `silentpaymentindex=1` stamps one `sp_tweaks` row per block
  from taproot activation upward, in the same atomic RocksDB batch as the
  chainstate. Each row embeds the hash of the block it describes, so readers
  verify identity without consulting the height→hash index.
- **Deferred backfill.** `backfillindex silentpayment` fills the pre-flag
  history, resuming from a 1000-block checkpoint across a restart or `kill -9`,
  with `pauseindex` / `resumeindex` / `cancelindex` and a `getindexinfo`
  section reporting enabled/synced flags, cursor heights and ETA.
- **Tier 1 — tweak firehose (zero custody).** A `tweaks` streaming category
  (bit 8, deliberately *not* in the `categories=0` default) carrying per-block
  `BlockTweaks`. A tweaks-only subscription cold-syncs the whole taproot era in
  one subscription, exempt from the 10,000-block replay clamp. JSON-RPC
  fallback: `getsilentpaymentblockdata`.
- **Tier 1.5 — mempool tweaks.** The same tweak computed at mempool admission
  and emitted as `MempoolTweak`, so a zero-custody client learns of a payment
  before confirmation. Opt-in per subscription; ephemeral, with no cursor.
- **Tier 2 — scan-key watch.** Register up to 16 `(b_scan, B_spend)` targets per
  connection and let the node do the ECDH, receiving `SilentPaymentMatched` for
  confirmed *and* mempool payments. The wallet re-derives the output key offline
  — the node never holds spend authority. The scan secret is in-memory per
  connection, zeroized on drop, never persisted or logged. Historical
  `RescanBlocks` is index-accelerated when the index is complete.
- **Rust and Go SDKs** cover both modes with typed events and runnable examples
  (`sp_light_scan`, `sp_wallet`).
- **`sat-tui`** gains an `sp-idx` column, rendered only when the index is on.
- **Measured, not estimated, footprint.** A full taproot-era mainnet index
  (252,520 blocks, 187,015,795 tweak entries) is about **13 GB**, not the ~4 GB
  previously quoted; growth is ~1 GB/year at current usage. The backfill took
  **6 h 46 m** (~10 blocks/s) on a node that stayed at the tip. `tweak_dust_limit`
  filters far less than documented — it is a bandwidth control for subscriptions,
  not a way to shrink the index. The rest of the disk-footprint table was
  re-measured on one fully-indexed node and several entries were off by orders
  of magnitude.
- A dedicated [Silent Payments (BIP 352)](https://epochbtc.github.io/satd/silent-payments.html)
  chapter in the Operator Manual covers the design, the three consumption tiers,
  and an end-to-end integration in each.

## Alerting & node health

- **Six detectors**: `ibd_complete`, `tip_stall`, `disk_low`,
  `mempool_congested`, `peer_floor`, `deep_reorg`. Level-triggered with
  hysteresis — one `raised`, one `cleared`, no pager flap.
- **One detection, three surfaces**, driven from the same state machine so they
  cannot disagree: a streaming `status` event, a `getwarnings` entry (which also
  fires the Core-compatible `alertnotify` hook), and a
  `satd_alert_active{kind="…"}` gauge pre-registered at 0.
- **`status` is bit 16 and excluded from the `categories=0` default**, and needs
  `rpc:read` on top of `stream:subscribe` — it describes your host, not the
  public chain. Not emitted on ZMQ, which has no per-subscriber mask.
- **Durability by re-evaluation, not replay.** Detectors re-examine every
  condition at startup and re-raise what still stands.
- **Five hot-reloadable thresholds**, `0` to disable: `alerttipstallseconds`
  (3600), `alertdiskfreemb` (10240), `alertmempoolfullpct` (90),
  `alertpeerfloor` (3), `alertreorgdepth` (3). Three have network-dependent
  defaults so an alert never fires on a chain behaving as designed.
- **Signed webhooks via `alertfile=<path>`** — a TOML file of hooks filtered by
  category, kind and severity. The POST body is byte-identical to the WebSocket
  JSON for the same event; the HMAC covers the delivery metadata as well as the
  body; redirects are never followed; hook contents reload on SIGHUP.
  Specified normatively with test vectors in
  [`docs/api/webhooks.md`](../api/webhooks.md).
- **`reorgwebhook=` is absorbed, not replaced** — same payload, headers and
  retry schedule, now served by the new dispatcher off the consensus runtime.
- **Both SDKs** gain `Categories::STATUS` and typed status events with open,
  `#[non_exhaustive]` enums, plus a `health_watch` example.

**Fixes from the alerting review:** a changed `alertfile=` was silently ignored
on SIGHUP; the plaintext-HTTP gate wrongly waived IPv4 link-local (including the
cloud metadata address); `-alertnotify` for edge events is now rate-limited and
reports the *worst* occurrence in each window rather than the first; the active
warnings set is capped at 256 distinct ids.

## Go SDK (`satdevents`)

An independently versioned Go module at
[`clients/go/`](https://github.com/epochbtc/satd/tree/master/clients/go), in full
parity with the Rust SDK and documented in a new
[Go SDK](https://epochbtc.github.io/satd/go-sdk.html) manual chapter. Thirteen
runnable examples. Parity is enforced in CI, not by usage: every satd PR runs
the Go unit tests (including a protobuf-reflection test that fails when a
variant is added to the `.proto` without a Go decoder), builds all examples, and
runs the Go E2E suite against the same freshly built `satd` binary as the Rust
one.

Writing the port was also a review of the original: **four defects found in the
Go client were present in `satd-events-client` too** and are fixed in this
release — among them a failed cursor-store write reporting success on retry.

## Security

- **A bearer token no longer travels in cleartext by accident.** Both SDKs would
  send a token over an unencrypted connection with no error and no warning, and
  the node accepted the configuration that makes that a routable exposure. The
  node now refuses that configuration at startup and the SDKs error rather than
  send. See *Upgrade notes*.
- **The events-gRPC TLS listener now negotiates `h2` over ALPN.** A node with
  `eventsgrpctlscert`/`eventsgrpctlskey` set could not be reached by any
  conformant gRPC client, including this repo's own Rust SDK.

## Consensus

- **Three BIP 141 witness rules brought to exact Core parity** ([#548](https://github.com/epochbtc/satd/issues/548)).
  Witness bytes sit outside everything the block hash authenticates; satd's
  `CheckWitnessMalleation` equivalent was missing three cases Core enforces.
  **A block already on disk could fail the new rules** — see *Upgrade notes*.
- **Transaction finality now matches Core: the coinbase counts, and the cutoff
  is strict** ([#581](https://github.com/epochbtc/satd/issues/581)) — found by
  the nightly block-differential fuzzer running a live `bitcoind` as oracle.
- **The block-ingress mutation gate now matches Core's `IsBlockMutated`.**
- **Compact-block reconstruction no longer duplicates a transaction on a BIP 152
  short-ID collision** — craftable by a peer, or roughly 1 in 2⁴⁸ by chance.
- **Median-time-past could come from a branch that had already lost.** A reorg
  updated the timestamp cache only for the block that triggered it, so every
  height the reorg replaced kept the *displaced* branch's timestamp. MTP gates
  BIP 113 locktimes and BIP 68 sequence locks.
- One **deliberate remaining difference** from Core (witness rules vs. weight
  check ordering) is documented rather than silently carried.

## Storage & chain integrity

Several of these were found in one production incident and the audit that
followed it.

- **The tip can no longer stand on blocks that were never connected.** satd
  refuses to connect onto a parent it never connected, and refuses to start on a
  tip that stands on a hole.
- **A reorg and the block connector could destroy each other's work.** The
  connector was the one chain mutator not taking `accept_lock`; an
  `invalidateblock` racing it rolled back and took eight already-committed
  blocks with it. The rollback now also checks the assumption it rests on.
- **A crash could strand a block's index entry over block bytes that never
  landed.** Block writes are now fsync'd before the referencing index entry is
  committed — see *Upgrade notes*.
- **`getblockfrompeer`** (Core-compatible) repairs a lost block without a resync.
- **The coin cache can no longer resurrect a spent coin**
  ([#583](https://github.com/epochbtc/satd/issues/583)) — a node wedged for 54
  hours looping `bad-txns-BIP30` after an ordinary one-block reorg.
- **A failed UTXO-cache flush no longer throws the delta away.**
- **A reorg could delete the height and txindex rows the replacement block had
  just written** — a batching defect where removes annihilated the puts.
- **The height index is now audited and rebuilt at startup** by walking parent
  pointers down from the tip; a missing row never needed a reindex to fix.
- **`invalidateblock` no longer strands the connector on the dead branch**, and
  now reports when it only half-worked.
- **A connector that stopped short of the headers tip no longer parks** until the
  next block, and no longer logs "giving up" and then keeps going.
- **`-reindex` now picks the most-work branch at a fork** instead of connecting
  every block reachable in the on-disk block *tree*; **`-reindex-chainstate`
  selects by chainwork** instead of trusting the derived height index; and a
  reindex now **validates the blocks it replays** and the index it reads them
  through, starting at genesis or refusing.
- **A reindex that cannot replay a block now stops instead of bricking** the
  datadir it was meant to recover.
- **Unreadable block data is reported as corruption, not silence.**
- **Core v28+ XOR-obfuscated block files (`blocksxor`)** are read and written;
  plaintext stays the satd default.
- **`satd-chainstate-audit`**, a shipped tool that checks a datadir's UTXO set
  against its own blocks, plus an in-node `verify_chainstate` consistency check.
- **A reorg now leaves a record of itself** in the log and in `getreorghistory`.
- **`/readyz` notices a connector that cannot make progress.**
- **`loadtxoutset` now freezes the chainstate it is loading into.**
- Correctness of reporting: **`confirmations` distinguishes the active chain
  from a losing branch** (Core's `-1`, where satd reported the depth the height
  implied), **`mediantime` is now a median**, and
  **`bad-txns-inputs-missingorspent` now says which outpoint**.

## Mempool & mining

- **The mempool now refuses transactions the next block cannot include**
  ([#588](https://github.com/epochbtc/satd/issues/588)). Admission enforced no
  finality of any kind, so a non-final transaction flowed straight into
  `getblocktemplate` and a miner using satd's template mined a block every
  validator rejects.
- **Block templates are now valid by construction**
  ([#589](https://github.com/epochbtc/satd/issues/589)) — CPFP children were
  emitted before their parents.

## Index backfills

- **The ETA now measures working time, not wall-clock.** It extrapolated idle
  time as work, so a backfill paused 48 h at 10% reported 20 days remaining
  against an actual ~54 hours. Applies to all three backfills.
- **Every DB-backed index now tells Prometheus whether it will serve**
  ([#558](https://github.com/epochbtc/satd/issues/558)) — the filter index
  exported no metric at all, and a failed address backfill took the Electrum and
  Esplora address surfaces offline with no signal.
- **The filter backfill resumes across a restart again**
  ([#555](https://github.com/epochbtc/satd/issues/555)) — the coin cache did not
  forward the filter-cursor methods to the store, so trait defaults answered.

## Logging

- Per-transaction mempool acceptance moved from `info` to `debug`.
- ANSI color is auto-detected (`NO_COLOR` honoured), so captured logs stay clean.

## Upgrade notes

**A remote events-gRPC bind with bearer auth now requires TLS.** If you run
`eventsgrpcallowremote=1` with `eventsgrpcauth=1` and no certificate, the node
will refuse to start on this release. Either set `eventsgrpctlscert` and
`eventsgrpctlskey`, or switch to `eventsgrpcmtls=1`, or bind loopback behind a
TLS-terminating proxy and drop `eventsgrpcallowremote`. This is a deliberate
break: the previous configuration put a bearer token — and any BIP 352 scan key
registered over the stream — on the wire in the clear. Loopback binds and mTLS
deployments are unaffected.

**SDK callers pairing a bearer token with a plaintext endpoint now get an
error** rather than a silent cleartext send. Use TLS, or
`insecure_bearer_token` / `WithInsecureBearerToken` for loopback and tests.

**A webhook URL of `http://169.254.x.x/...` now fails at startup.** The
plaintext-HTTP gate no longer waives IPv4 link-local, and a bad `alertfile` is
fatal at startup by design. Move the hook to `https://` or add
`allow_insecure_http = true` to that `[[webhook]]` stanza **before** upgrading.
No other address range changed.

**`reorgwebhook=` no longer follows redirects.** A receiver answering `3xx` now
has its record retried three times and then dropped. Point the key at the final
URL.

**Block writes are now fsync'd.** A block's flat-file record is made durable
before the index entry referencing it is committed, on every write path
including initial block download. This is a correctness fix, not a tunable, and
it costs one fsync per stored block; expect some IBD throughput cost against
0.4.0 on slower storage.

**Existing datadirs are not audited on upgrade.** If an earlier crash left an
index entry pointing at block data that never reached disk, that hole persists
until it is repaired with `getblockfrompeer` — see
[Repairing lost block data](https://epochbtc.github.io/satd/disk-footprint.html#repairing-lost-block-data).
The symptom is a single block returning `-5 Block data not available` on a node
that is not pruning.

**A block already on disk could fail the new witness rules.** Every earlier satd
version accepted and stored the three classes at issue, and none of them changes
the block hash or merkle root. This release closes the ingress path, so such a block can no longer be
accepted; one already stored connects as before until the datadir is
reindexed, at which point the replay rejects it.

**Re-run an old reindex.** If you ran `-reindex` on 0.4.x or earlier against a
datadir that had been live through a reorg, re-run it on this release. A reindex
that aborted with `bad-txns-inputs-missingorspent` left nothing usable; one that
completed may have a UTXO set that silently disagrees with consensus. The same
applies to `-reindex-chainstate` over a datadir that had logged `bad-cb-height`
or any other sign of a damaged block index.

**Otherwise no action required.** The silent-payment index is off by default;
with the flag unset, a node's defaults and on-disk behavior are byte-identical
to 0.4.0. `blocksxor` is likewise a drop-in — existing datadirs stay plaintext,
and the only on-disk change is a new all-zero 8-byte `blocks/xor.dat`. Note that
a blocks dir *created* with `blocksxor=1` is not readable by satd 0.4.x.

  [`SECURITY.md`](../../SECURITY.md).

  images with cosign (keyless OIDC), and git tags with SSH signatures (no GPG).
  The key matrix and verification steps are in
  [`SECURITY.md`](../../SECURITY.md).

  [`CORE_DIFFERENCES.md`](../../CORE_DIFFERENCES.md).
- **Operating satd** — observability, the full flag matrix, tuning, and the
  downstream packaging contract live in the
  [Operator Manual](https://epochbtc.github.io/satd/).
