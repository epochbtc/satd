# satd 0.6.0

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.6.0 builds a **solo-mining server** into the node, Stratum V1 and V2
with Job Declaration, so a miner can point its hardware at its own node with
no pool and no proxy. It adds **silent-payment sending** (BIP 375 over PSBT
version 2), completing the receive side shipped in 0.5.0, and re-keys every
index on transaction ordinals, which **halves a fully indexed chainstate**.
The rest is sync, reorg and reindex robustness, and another round of Bitcoin
Core parity found by running Core's own functional tests against satd.

**One chainstate rebuild is required.** The chainstate schema moves from 3 to
7, so the first start runs one `-reindex-chainstate` from the block files
already on disk; app-store installs do it by themselves, and pruned nodes
must resync. See *Upgrade notes*. The new listeners are off unless you turn
them on, and defaults stay Bitcoin Core-compatible.

## Highlights

- **Stratum V1 and V2 solo-mining server.** Mine to your own address from
  your own node, with TLS for V1, Noise for V2, Job Declaration, and
  per-miner statistics. See [Mining](#mining).
- **Silent-payment sending (BIP 375).** PSBT version 2 on every PSBT method;
  `analyzepsbt` and `finalizepsbt` verify every silent payment output before
  it can be broadcast, and `sat-cli` signs. The node stays keyless.
- **A fully indexed chainstate is half the size.** Indexes key on 5-byte
  transaction ordinals instead of 32-byte txids: a synced mainnet node with
  every index went from 805 GB to 388 GB.
- **Block templates match Bitcoin Core's**: the right difficulty at a
  retarget, the sigop limit, CPFP package selection, `-blockmaxweight`, and a
  validity check on every template before a miner sees it.
- **Faster block relay**: BIP 152 high-bandwidth compact blocks, compact
  fetches for blocks announced by `headers`, and BIP 339 wtxid relay.
- **Install from Umbrel's community store or a signed appliance image** for
  amd64 and arm64, each opening onto a new status page; the StartOS package
  is submitted to Start9's registry. See
  [Installing satd](https://epochbtc.github.io/satd/installing.html).

## Mining

### The Stratum server

- **Stratum V1** (`--stratum=1`). A miner connects to the node and gets work
  built from the node's own template; a found block is accepted and relayed
  by the same process. The username is the payout address
  (`<address>.<worker>`, `--stratumaddress` as the fallback) and the coinbase
  pays it the whole reward: there is no share accounting, as with
  `ckpool -B`. The plaintext listener binds loopback, and a non-loopback
  plaintext bind is refused unless `--stratumallowplaintextremote=1`, because
  V1 carries the payout address in cleartext. TLS and mTLS are on
  `--stratumtlsbind`; AxeOS stores at most 511 bytes of custom CA, so the
  manual gives a CA recipe that fits and satd warns when a chain ends in a
  larger one. No work is served during initial block download, and the server
  is refused on signet, whose blocks need the network's signing key (#746).
- **Stratum V2** (`--stratumv2bind`): the Mining Protocol over Noise NX, with
  standard and extended channels (AxeOS 2.14 and later uses extended). The
  authority key is created once at `<datadir>/stratum_v2.key` (mode 0600,
  `--stratumv2key` to override) and logged in hex and base58check. Miners pin
  it, so it survives restarts, a malformed key file stops the node rather than
  being replaced, and it belongs in your datadir backups (#748).
- **Job Declaration** (`--stratumv2jd=1`), with solo semantics: a miner
  running a Job Declarator Client chooses its block's transactions. Every
  declared transaction must already be in this node's mempool in minable
  order, and the coinbase must build on the current tip, pay the token's
  address and claim no more than the subsidy plus the declared fees (#751).
- **Seeing your miners.** `getstratuminfo` reports the listeners, the
  authority key, channels, share counters, blocks found, the current job, and
  a `miners` array with each miner's device, difficulty, shares, best share
  and estimated hashrate. The metrics endpoint exports node-wide
  `satd_stratum_*` series. `-debug=stratum` logs per-miner detail; a
  disconnect summary and every refused share, with its reason, are always
  logged. See
  [Verifying a miner](https://epochbtc.github.io/satd/stratum.html#verifying-a-miner).
- **A found block is saved before it is submitted**, to
  `<datadir>/stratum/found/<height>-<hash>.hex`. If the node refuses it, the
  warning names the file, and `sat-cli -stdin submitblock < <file>` sends it
  to any node.
- **Miners are not dropped between shares.** Every connection used to be
  closed after 120 seconds without a message, so a miner on vardiff's 30-second
  target was dropped about every half hour and restarted at its lowest
  difficulty. An authorized miner may now stay quiet for twenty expected share
  intervals, between 2 minutes and a day.
- **Steadier difficulty.** Vardiff moves only when the shares since the last
  change are significantly off target, leaves a rate within 15% alone, and
  steps by at most ×8. In simulation over five hours, 95% of settled miners
  kept their difficulty within a ×1.55 range with at most two changes; the
  old rule's median was a ×17 range and about 170 changes. Slow "lottery"
  devices (ESP32-class, about 1 MH/s) reach difficulty 1 in about twelve
  minutes. They were closed as idle before vardiff could lower them, about 140
  times a day, and averaged two shares a day.
- **Work follows a tip reached through block download**, where it stayed on
  the old tip for up to 30 seconds after the node caught up.

### Block templates

- **The right difficulty at a retarget.** Templates carried the previous
  block's `nBits`, so a miner on mainnet at every 2016th height, and on the
  testnets after any 20-minute gap, found a block the node itself rejected as
  `bad-diffbits`. `mintime` is now median time past plus one, Core's value.
- **Every template is checked before it is used**, as Core's
  `TestBlockValidity` checks its own. A structural check runs on each
  template; `getblocktemplate` and the `generate` RPCs refuse a failing one
  with `TestBlockValidity failed: <reason>`, and the Stratum server hands out
  a coinbase-only job instead. A full check with scripts follows in the
  background. A failure is a node bug: it is logged with the offending
  transaction, counted in `satd_template_checks_total`, and raised as the new
  critical `template_invalid` alert.
- **Templates keep to the sigop limit.** A mempool dense in bare multisig
  filled the 80,000 sigop budget long before the weight limit, and the
  template made a block the node refuses. 400 are now reserved for the
  coinbase, as in Core, and `getblocktemplate` reports each transaction's
  `sigops`.
- **Transactions are selected by package**, with Core's ancestor-score
  algorithm. A child paying for a cheap parent (a CPFP bump, a Lightning
  anchor spend, a zero-fee parent with ephemeral dust) waited on the parent's
  own fee rate and was often left out; the fees went with it.
- **`-blockmaxweight` takes effect** (#836). It was parsed and read by
  nothing. It now caps every template with Core's semantics, and a value above
  the consensus maximum or a malformed one in `bitcoin.conf` stops the node.

## Silent payments: sending

- **PSBT version 2 everywhere.** Every PSBT method accepts and answers a
  version 2 PSBT and carries the BIP 375 fields, and any field it does not
  recognise, byte for byte. `combinepsbt` refuses two values for one key
  rather than keeping the first, and `joinpsbts` refuses a silent payment PSBT
  that has committed to its inputs. Version 0 behaviour is unchanged, error
  text included.
- **Verification before broadcast.** A wrong ECDH share sends the money to a
  key nobody holds, with nothing visible on chain. `analyzepsbt` returns a
  per-output status (`ready`, `missing_shares`, `invalid_proof`, …) with the
  script satd derived independently, and `finalizepsbt` refuses to extract
  unless every silent payment output verifies; there is no override. Beyond
  BIP 375's reference validator, satd requires each input's public key to
  match the output it spends and checks every previous output against its own
  UTXO set. The verifier is tested against the BIP 374, BIP 375 and BIP 352
  vectors, and end to end with the node's tweak index and a scan-key watch
  both finding the payment.
- **Creating one.** `createpsbt` accepts an `sp1…` address as an output key
  with a new trailing `psbt_version=2`; a positional call written against
  Core keeps its meaning. `decodepsbt` and `analyzepsbt` spell the recipient
  back as its address. `createrawtransaction` refuses an `sp1…` key and says
  why.
- **Signing one.** `sat-cli signpsbtwithkey` is a BIP 375 Signer: it
  computes and proves the shares for the inputs it holds, derives every output
  script once all eligible inputs are covered, and only then signs. A signer
  holding some of the inputs writes its shares and exits 2, and the next
  signer continues. `sat-cli signpsbtwithsigner` passes a version 2 PSBT to an
  external signer and refuses a reply that does not verify.

BIP 375 is still a draft. See
[Sending](https://epochbtc.github.io/satd/silent-payments.html#sending-bip-375)
in the Operator Manual.

## Storage

- **Every index keys on transaction ordinals** (schema 3 → 7). An ordinal
  numbers transactions in chain order, so 5 bytes replace a 32-byte txid that
  was stored five to seven times over. The transaction index, the spend index
  (76 bytes a row → 16), address funding rows (64 → 32) and address spending
  rows (92 → 32) all move. On a synced, fully indexed node the chainstate
  went from **805 GB to 388 GB on mainnet** (−52%), −43% on signet and −40%
  on testnet4. Nothing on any wire changes, iteration order included.
  `getrawtransaction` indexes straight into its block, and Esplora's
  `/outspends` is one prefix scan. A node with neither `-txindex` nor
  `-addressindex` writes no index rows, as before.
- **AssumeUTXO indexes are no longer reported complete too early.** Loading a
  snapshot left the address and spend indexes marked complete, so they
  answered "no history" and "unspent" for the chain below the snapshot base.
  They now refuse until `backfillindex address` has run, the procedure that
  was already documented.
- **UTXO counters stay exact across reorgs.** `gettxoutsetinfo`'s `txouts`
  and `total_amount` drifted on every reorg whose new branch re-mined the old
  block's transactions; on signet, eleven one-block reorgs left them 19,547
  coins away from the coin set, and `dumptxoutset` refused. The coins were
  right throughout, and the upgrade's rebuild corrects the counters.
- **Exact recent UTXO ages.** `utxo_age_distribution`'s `<1h`, `<1d`, `<1w`
  and `<1mo` buckets are exact, with a new `exact` field; `<1d` was always
  empty or a whole 1000-block chunk. No reindex: an existing datadir builds
  the window with one background scan.
- **`getstoragefootprint`** (and `sat-cli debug storage-footprint`) reports
  each column family's disk bytes, key estimate, bytes per key and pending
  compaction on a live node, without an offline `ldb` dump.
- **A missing cumulative transaction count is an error**, not a silent
  restart at zero. Fixing it also fixed `getchaintxstats` totals, which were
  one short for the life of any datadir that had run `-reindex-chainstate`.

## Chain, sync and reindex

- **Reorgs wait for the whole branch, and take it when it arrives** (#739,
  #856, #861). satd disconnected its chain for a heavier branch before
  checking that the branch's blocks had arrived, then rolled back with an
  `ERROR`, which was routine on testnet4. It now activates only a branch whose
  blocks all have data, and does so as soon as the last one arrives instead of
  waiting for the next block. A race between the downloader and the connector
  that could stop sync for good is fixed. Connecting stored blocks above the
  tip is no longer reported as a reorg.
- **Pruning keeps blocks the node has not connected yet.** A pruned node in
  initial sync deleted block files that also held blocks downloaded ahead of
  its tip, then retried the next block forever. A file now goes only when
  every block in it is at or below the cut, as in Core. A stored block whose
  record is gone is now fetched again from a peer by itself.
- **An interrupted rebuild is no longer served** (#839). A `-reindex-chainstate`
  or `-reindex` cut short left a datadir that looked finished, with its
  indexes marked complete, and stuck at the height it reached. A marker now
  makes the next plain start refuse and name the flag that finishes the job.
- **`-upgradechainstate=1`** runs `-reindex-chainstate` when the chainstate's
  schema is older than the binary's or a rebuild did not finish, and does
  nothing otherwise, so it can stay on. It never downgrades and refuses a
  pruned node. Core has no equivalent; the app-store packages turn it on.
- **A `-reindex` over missing block files says so** (#504). It stopped at
  the first missing `blk*.dat` and still logged `Reindex from flat files
  complete`. The replay is now held to the tip the node had reached, and the
  `reindex.short` warning names the missing file.
- **A clean shutdown no longer ends in a crash** (#868). A node stopped during
  initial sync could log `satd stopped` and then die of SIGSEGV, because the
  block connector kept running into the exit. Shutdown now stops it before
  the flush and exits without C++ static destructors. On a pruned signet node
  in initial sync, the previous build crashed in 3 of 14 stops; this one
  exited cleanly in 20 of 20, each within 21 seconds.
- **A reload sent during startup no longer stops the node.** The `SIGHUP` and
  `SIGUSR1` handlers are installed as startup begins.
- **A node that mined its own chain takes relayed transactions** (#759); it
  read as still in initial block download and ignored them.
- **`invalidateblock`, `reconsiderblock` and `preciousblock` behave as in
  Core.** The header tip leaves an invalidated branch (#778),
  `reconsiderblock` clears the block's ancestors as well as its descendants,
  and `preciousblock`, which was a stub, works. Equal-work tips are ordered by
  Core's `nSequenceId` rather than by block hash.
- **`verificationprogress` is Core's estimate** (#744), equal to Bitcoin Core
  v31.1's. It read 0.69 at genesis.

## Consensus

- **The BIP 34 height must be Core's exact encoding.** satd accepted the right
  height pushed non-minimally (padded, with a needless sign byte, as
  `OP_PUSHDATA1`), which Core rejects as `bad-cb-height`. No block on a public
  network does this, but one would have split satd from Core. Job Declaration
  applies the same rule to a declared coinbase.
- **Signet block solutions are verified** (#767, #837). The default signet's
  were never checked, so a node followed any block that met signet's trivial
  proof of work. Custom signets signed with Core's tooling never verified
  either: satd's BIP 325 `to_spend` lacked its leading `OP_0`. Verification
  starts at your tip, and stored blocks are checked on the next rebuild, which
  this upgrade runs. One gap
  remains: signet `nBits` is not checked against the retarget schedule (#838).

## Networking

- **Compact block relay, hardened** (#763). A `cmpctblock`'s header is
  checked before the block is rebuilt, pending reconstructions are bounded per
  peer, a block being rebuilt is no longer also downloaded in full, and a
  merkle mismatch falls back to the full block without penalising the peer.
- **High-bandwidth compact block relay** (#770). satd selects up to three
  high-bandwidth peers and announces a new block to them as a `cmpctblock`
  before connecting it, including every block found through the Stratum
  server. A solo miner's block reached the network later on satd than on
  Core. `getpeerinfo` reports `bip152_hb_to` and `bip152_hb_from`.
- **Blocks announced by `headers` are fetched as compact blocks** (#867), on
  Core's conditions, with the full block as the fallback; satd fetched every
  block whole from a peer it had not picked for high-bandwidth relay.
  `sendheaders` goes to inbound peers too.
- **Reconstruction statistics.** One `compact block reconstructed` log line
  per block and `satd_net_compact_block_*` metrics say how each block was
  rebuilt. `-blockreconstructionextratxn`, accepted and ignored before, now
  sizes Core's extra-transaction pool (default 100).
- **Opt-in compact block prefill** (`-cmpctblockprefill=1`, up to
  `-cmpctblockprefillbytes`, default 8192): announces a block with the
  transactions this node lacked already inside, following Core's unmerged
  proposal #35558. Off by default.
- **Wtxid relay (BIP 339)** (#714). A peer that negotiates it, as every Core
  since 0.21 does, is announced transactions by wtxid and can fetch them by
  wtxid. Two transactions with one txid and different witnesses are told
  apart: the second is refused as `txn-same-nonwitness-data-in-mempool`.
- **Addresses from gossip** (#866). An address naming no host (`0.0.0.0`,
  `::`) is never dialled; satd dialled a gossiped `0.0.0.0`, which on Linux
  reaches the local host. Off regtest the address book takes routable
  addresses only, as Core's does. A peer found through gossip is
  `outbound-full-relay`, not `manual`; see *Upgrade notes*.
- **Peer names are looked up again** (#876, #879). An `-addnode` or
  `-connect` name that does not resolve yet is kept and retried instead of
  dropped, a disconnected named peer is looked up again before it is
  redialled, and a config reload registers new entries as startup does.
- **An honest peer is no longer banned** for headers the node cannot connect
  yet, which could cut a syncing node off from its only peer. The P2P loop
  also stops waiting out its 500 ms tick while its queue is full, which capped
  initial block download at 64 messages per tick.
- **A `pong` answers for everything sent before the `ping`**, as in Core, so
  `send_and_ping(block)` means the block is connected.

## JSON-RPC and listeners

- **Large replies are served** (#723). One 20 MiB cap governed requests and
  replies, so `getrawmempool verbose` failed with `-32008` above roughly
  17,000 mempool transactions. Requests keep the 20 MiB cap; replies are
  bounded at 256 MiB, which covers the default `-maxmempool`.
- **`getmempoolsummary [top_n]`**: a size histogram and the top transactions
  by ancestor fee rate, about 9 KB where `getrawmempool verbose` is about
  85 MiB and four seconds of node CPU on a mainnet-sized mempool.
- **Connection caps hold** (#813). The TLS RPC listener's cap of 100 counted
  only connections still in their handshake, so idle keepalive connections
  could exhaust file descriptors. A peer outside `-rpcallowip` no longer takes
  a slot, and at-capacity warnings are rate-limited.
- **A configured `-rpcallowip` gates the TLS RPC listener too**, and
  `-rpcreadonlyallowip` the read-only one. The packaged configurations now
  write `rpcallowip=0.0.0.0/0`, since their TLS listener serves the LAN and
  their plain one is kept off it by the network (#887). See *Upgrade notes*.
- **Esplora and `streamws` cap their sockets.** They bounded nothing at the
  socket level and never closed an idle keep-alive connection.
  `-esploramaxsockets` and `--streamws-max-sockets` (default 1024) now apply,
  idle connections close, and an open WebSocket keeps its slot. A mistyped cap
  is clamped to 100,000 instead of crashing satd at boot.
- **HTTP/1.1 only** on the JSON-RPC, Esplora and `streamws` listeners, so
  `-rpcservertimeout` cuts a client that connects and sends nothing; see
  *Upgrade notes*.

## Authentication

- **`-rpcwhitelist` and `-rpcwhitelistdefault`** limit an RPC user to a list
  of methods, with Core's semantics. Both used to stop satd at startup. A user
  with a list is refused a WebSocket upgrade, and bearer tokens are
  unaffected. See [Authentication](https://epochbtc.github.io/satd/authentication.html).
- **An `rpc:submit` bearer capability**, so a broadcaster's token can hold
  `rpc:read` and `rpc:submit` and never `stop` the node. `rpc:write` implies
  it, so existing tokens keep broadcasting.
- **Esplora's `POST /tx` needs `rpc:submit`**; an `esplora:read` token alone
  could broadcast.
- **Batches and WebSocket calls are charged per call** against a token's
  `rate_limit`. A batch counted as one call however many it carried. A call
  over budget is answered `-32005` with `retry_after_secs`.

## Observability

- **Metrics and health over TLS.** `-metricstlsbind` serves `/metrics`,
  `/healthz` and `/readyz` on a second port, with optional client
  certificates (`-metricsmtls`), so Prometheus can scrape across a network
  without a proxy (#752).
- **A status page** (`statuspage=1`) on the metrics listener: a single-page,
  self-refreshing view of sync, indexes, mempool, fees and peers for a
  browser. It is unauthenticated like `/metrics`, so it shows no credentials,
  addresses or error text, and connection strings come only from
  `statusadvertise` (#749).
- **The metrics listener answers while the node starts** (#841), including
  through a mainnet rebuild that takes hours: `/readyz` is 503 with what the
  node is doing, `/metrics` carries `satd_startup_*` gauges, and the status
  page shows the rebuild's progress and ETA.
- **`tip_stall` no longer fires during initial sync** (#814). Every first
  mainnet sync raised a critical alert an hour in and held it to the end.
- **`sat-tui`**: the mempool and UTXO-age histograms are log-scaled bar charts
  with their counts, the mempool panels read `getmempoolsummary`, and a
  failing RPC is named in the title bar (`rpc failing: <method>`) instead of
  leaving its panel frozen.

## Bitcoin Core parity

These came from running more of Core's functional suite against satd.
`mining_mainnet`, `mining_getblocktemplate_longpoll`, `mempool_expiry`,
`mempool_accept_wtxid`, `feature_signet`, `feature_fastprune`,
`feature_maxtipage`, `rpc_bind`, `rpc_users`, `rpc_setban`, `rpc_whitelist`,
`p2p_compactblocks_hb`, `p2p_compactblocks_blocksonly`, `p2p_feefilter`,
`p2p_handshake`, `p2p_net_deadlock`, `p2p_nobloomfilter_messages`,
`p2p_ping`, `p2p_timeouts`, `p2p_tx_privacy` and `p2p_v2_transport` now run
in the pull-request gate.

- **RPC fields.** `getmininginfo` reports `bits`, `target`, `blockmintxfee`
  and the next block's `height`, `bits`, `difficulty` and `target`; `target`
  appears beside `bits` in `getblock`, `getblockheader`, `getblockchaininfo`
  and `getchainstates`; signet nodes report `signet_challenge`;
  `getprioritisedtransactions` reports `modified_fee`; `getmempoolentry`
  reports `wtxid`.
- **Address-manager RPCs**: `getnodeaddresses`, `getaddrmaninfo`, and the
  hidden `addpeeraddress` and `getrawaddrman`. `peers.dat` moves to format
  version 2; a version 1 file still loads.
- **Mempool policy.** A full mempool raises a rolling minimum fee
  (`mempool min fee not met`), reports it in `getmempoolinfo`, and advertises
  it in `feefilter`. Rejections read `reason, detail` as Core's do;
  `getrawmempool` takes `mempool_sequence=true`; an expired transaction takes
  its descendants with it.
- **A rejected script names the rule it broke**:
  `mempool-script-verify-flag-failed (Non-canonical DER signature)` rather
  than `ERR_SCRIPT`, and `testmempoolaccept` names the input.
- **Mining.** `getblocktemplate` long polling waits for a new tip or a
  mempool change. `generatetoaddress`, `generatetodescriptor` and
  `generateblock` run on every chain, and their blocks always carry the
  witness commitment.
- **Manual pruning.** `-prune=1` puts the node in prune mode with no budget,
  and the new `pruneblockchain` RPC is the only thing that deletes. `-fastprune`
  is Core's 64 KiB block-file size.
- **Options that were accepted and ignored now work**: `-maxtipage`,
  `-rpcservertimeout` in `bitcoin.conf`, `mocktime=` in `bitcoin.conf`, and
  `-peertimeout`. With no `-rpcbind` the RPC server listens on `::1` as well as
  `127.0.0.1`. `-norpcauth`, `-norpccookiefile`, bracketed IPv6 in
  `-rpcallowip`, `-cjdnsreachable` and Core's `-noX=0` double negative are
  accepted, and bad `-rpcbind`, `-rpcauth` and cookie-file settings stop the
  node with Core's messages.
- **P2P.** BIP 324 v2 detection, `addnode`'s `v2transport` argument,
  `feefilter` rules, protocol-violation disconnects, ping timing on the node
  clock, Core's handshake rules (service flags, connections to ourselves) and
  Core's log lines. A 4 MB message over v2 is accepted, and initial block
  download asks a peer only for blocks it has announced.
- **Signet**: an invalid solution is `bad-signet-blksig`, and a repeated or
  non-hex `-signetchallenge` is refused in Core's words.
- **`sat-cli` reads `bitcoin.conf` like `bitcoin-cli`**: `rpcuser`,
  `rpcpassword`, `rpccookiefile`, `rpcport`, `rpcconnect` and the chain, with
  `-conf`, `-signet`, `-testnet4` and `-chain=`. A node configured with
  `rpcuser`/`rpcpassword` writes no cookie, and `sat-cli` could not reach it
  without repeating them.

## App stores, appliance and packaging

- **Where to get it.** Umbrel: add the community store
  `https://github.com/epochbtc/umbrel-apps` and install **satd**. StartOS: the
  package is submitted to Start9's community registry; until it is listed,
  build [`epochbtc/satd-startos`](https://github.com/epochbtc/satd-startos)
  and sideload it. Appliance images for **amd64 and arm64**, in `core` and
  `desktop` flavours, are attached to this release and signed with the release
  minisign key. The new
  [Installing satd](https://epochbtc.github.io/satd/installing.html) chapter
  covers each, plus the container image and the tarballs.
- **Chainstate upgrades without a shell.** `satd-init` writes
  `upgradechainstate=1`, so an app-store node rebuilds its chainstate by
  itself on the first start of this release and restarts a rebuild a power
  cut interrupted.
- **Both packages open onto the status page**; the appliance turns it on, and
  the reference stack and the appliance serve metrics and the page over TLS on
  9336.
- **Umbrel uses its own host ports** (8430, 8433, 8436, 8439, 50012, and 8431
  for Esplora over TLS), so it installs beside Bitcoin Node, Fulcrum and Ride
  The Lightning, and its backups leave the chain out.
- **StartOS** backups skip the AssumeUTXO background chainstate, and its sync
  check shows blocks against headers instead of the old
  `verificationprogress`.

## Streaming API & SDKs

- **The node advertises its version** on every gRPC stream, in the
  `satd-version` and `satd-events-schema` response headers.
- **The SDK compatibility rule is written down** in
  [`STABILITY_POLICY.md`](../../STABILITY_POLICY.md#streaming-api--sdk-compatibility):
  an SDK works with any node of the same schema version at or above its own
  version.
- **Both SDKs apply it.** A node one minor version behind gets a warning; two
  or more behind is refused (`StreamError::NodeTooOld` / `ErrNodeTooOld`,
  overridden by `allow_old_node()` / `WithAllowOldNode()`), as is any schema
  mismatch.
- **The Go SDK is versioned with the node**: `satdevents.Version` equals the

## Upgrade notes

- **One `-reindex-chainstate`, once.** The chainstate schema moved from 3 to
  7 across four changes in this release, and an earlier datadir is refused at
  startup with a message naming the flag. That is **one** rebuild, not four:
  the replay discards the RocksDB chainstate and replays the block files into
  a new one, building every enabled index inline as it goes. The block files
  are never touched, so nothing is downloaded again, and because the old
  column families are dropped before the replay starts, the datadir never
  grows beyond its current size during the rebuild. Budget roughly what an
  `-assumevalid` sync of the same chain costs on your hardware.

  App-store and reference-stack installs do this by themselves on the first
  start: their generated configuration sets `upgradechainstate=1`. The status
  page shows the progress, and a rebuild interrupted by a power cut starts
  again on the next boot without any action.

  There is no downgrade. 0.5.x refuses a schema 7 chainstate as this release
  refuses theirs, so going back means another rebuild under the older
  release. A rebuild refused before it starts (a pruned node, a gap in the
  block files) leaves the chainstate untouched, so the previous release can
  still open it.

  Two cases need more:

  - **Pruned nodes must resync.** The replay needs every block and a pruned
    node does not have them. `-upgradechainstate` refuses them with a message
    saying so rather than starting a rebuild it cannot finish.
  - **AssumeUTXO nodes**: finish or discard background validation before
    upgrading: a background chainstate at the old schema is refused, and
    `-upgradechainstate` does not rebuild it. Then, unchanged procedure: run
    `backfillindex address` once background validation has reached the
    snapshot base. This release also enforces it: loading a snapshot now marks
    the address and spend indexes incomplete until the backfill has run.

- **A configured `-rpcallowip` now also gates `-rpctlsbind`**, and a
  configured `-rpcreadonlyallowip` gates `-rpcreadonlytlsbind`. The TLS
  JSON-RPC listeners never consulted either list. If you run one on a
  public address and its allowlist names only the clients of the
  plain-HTTP bind, add the TLS clients to the same list before upgrading.
  An empty `-rpcallowip` is unchanged: a TLS bind stays reachable from
  wherever it is bound, gated by TLS/mTLS and RPC auth.
- **The JSON-RPC, Esplora and streamws listeners serve HTTP/1.1 only.**
  They answered HTTP/2 as well to a client that started it without
  negotiation (h2c prior knowledge); none of them advertised it over TLS.
  A client configured for HTTP/2 prior knowledge against one of them must
  switch to HTTP/1.1. The events gRPC listener is separate and still speaks
  HTTP/2.
- **Esplora bearer tokens that broadcast need `rpc:submit`.** `POST /tx` no
  longer accepts a token holding only `esplora:read`; add `rpc:submit` (or
  `rpc:write`) to any token that broadcasts through Esplora, or it gets `403`.
  Operator credentials and the loopback default are unaffected.
- **Peers the node finds for itself are no longer `manual`** (#866). A peer
  reached through gossip, `peers.dat` or a DNS seed is now
  `outbound-full-relay`: it no longer takes `-whitelist` entries marked
  `out`, and one that does not offer `NODE_NETWORK | NODE_WITNESS` (or
  `NODE_NETWORK_LIMITED | NODE_WITNESS` while the tip is recent) is dropped
  at the handshake, as Core drops it. Name a peer with `-addnode` if it
  should keep `out` permissions. Off regtest, `peers.dat` entries for
  private, loopback and other non-routable addresses are dropped on the
  first start.
- **Options that were ignored now take effect.** Check your configuration
  for `-blockmaxweight` (it now caps templates, and a malformed value stops
  the node), `-maxtipage`, `-rpcservertimeout` in `bitcoin.conf`, and
  `-stopatheight` (it now stops a node in initial sync, and
  `-stopatheight=0` means off).
- **`/healthz` answers during startup**, so it says the process is up, not
  that startup has finished. A supervisor that polled it as a started signal
  should poll the JSON-RPC instead, which answers `-28` until the node is
  running.
- **Umbrel's ports changed.** A client configured against the package's old
  ports needs the new ones listed under *App stores, appliance and packaging*.
- **Go SDK tag jumps from `v0.1.0` to `v0.6.0`.** It now follows the node
  version: `go get github.com/epochbtc/satd/clients/go@v0.6.0`.
- **An SDK newer than its node now complains.** A 0.6 SDK (Rust or Go) logs a
  warning against a 0.5 node, and from 0.7 on an SDK refuses a node two minor
  versions behind. Upgrade nodes before clients, or pass `allow_old_node()` /
  `WithAllowOldNode()` while a rollout is in progress.
