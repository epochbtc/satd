# satd 0.6.0

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.6.0 is a minor release on the 0.x line. Planned scope: a **native
Stratum V1/V2 solo-mining server**, so a home miner can point hardware at its
own node without a pool or a translation proxy; **BIP 375 silent-payment
sending**, completing the send side of the receive support shipped in 0.5.0;
and a round of sync/reindex robustness and Bitcoin Core parity work.

A new listening surface is minor-version material, which is why this is 0.6.0
rather than a patch on the 0.5.x line.

This file accumulates entries as changes land; it is not yet a cut release.

## Highlights

- **Metrics over TLS.** Prometheus can scrape satd from another machine
  without a reverse proxy.
- **The Umbrel and StartOS packages are ready for their stores.** The Umbrel
  app installs beside Bitcoin Node, Fulcrum and Ride The Lightning, and
  neither package backs up the chain.

## Observability

### Metrics and health endpoints over TLS

`/metrics`, `/healthz` and `/readyz` were plain HTTP with no authentication,
so reaching them from another machine meant putting a TLS proxy in front.
`-metricstlsbind=<addr:port>`, with `-metricstlscert` and `-metricstlskey`,
now serves the same endpoints over TLS on a second port. The plain listener
keeps running beside it, so container healthchecks and local tools see no
change, and `-metricstlsbind` requires `-metricsport`.

TLS encrypts the scrape; it does not choose who may scrape. `-metricsmtls=1`
with `-metricsmtlsclientca` requires a client certificate, and
`-metricsmtlsclientallow` narrows that to named clients. Prometheus supports
both through `scheme: https` and `tls_config`. The certificate reloads on
`SIGUSR1`, as on the other TLS listeners. A certificate that does not load or
a port that cannot be bound stops satd at startup. See
[Observability](https://epochbtc.github.io/satd/observability.html#over-tls).

## `verificationprogress` is Core's estimate (#744)

`getblockchaininfo` and `getchainstates` reported `verificationprogress` as
the tip's timestamp divided by the current time, both counted from 1970. A
node at genesis read 0.69, and a year of blocks moved it by under two points.
The background chainstate's entry in `getchainstates` used a height ratio
instead.

Both now compute Bitcoin Core's `GuessVerificationProgress`: the chain's
cumulative transaction count against Core's per-network estimate of all
transactions to date, with a tip inside two hours of the clock placed by its
height against the best header. A synced node reads exactly 1, and drops below
it when a new header arrives. The values equal Bitcoin Core v31.1's for the
same chain and clock. That was checked on regtest across clock offsets from the
tip, with a header above it, and at genesis on mainnet, testnet3, testnet4 and
signet. A custom signet (`-signetchallenge`) has no estimate data, as in Core.

## App-store packages

Both packages now pin satd 0.5.2, the first release whose image carries
`satd-init`, and both are ready to publish: the Umbrel package to a community
app store, the StartOS package to Start9's community registry.
`contrib/packaging/sync-store.sh` copies each into the repository that serves
it, after checking the image pin names a release matching the package version.

### Umbrel: its own host ports

Umbrel has one host port space for every app on a device. The package used
3001, 8333 and 50002, which Ride The Lightning, Bitcoin Node and Fulcrum own,
so it could not be installed beside any of them. It now uses 8430 for the app
page, 8433 for P2P, 50012 for Electrum over TLS, 8436 for JSON-RPC over TLS
and 8439 for MCP, none of them used by another app in the store.

Each is mapped 1:1 with satd listening on the same number. P2P in particular
cannot be remapped on the host alone: satd advertises the port it listens on,
so peers would be sent to whichever node owns 8333. A client configured
against the old ports needs the new ones.

The package's backups leave out the chain and chainstate, and keep the
install's CA, MCP token and configuration. Before, a user with Umbrel backups
on backed up the whole chain.

### StartOS: backups and sync progress

Backups now leave out `chainstate_background/`, which holds a full coin set
while an AssumeUTXO snapshot validates. The list had been written from Bitcoin
Core's datadir layout; it named `indexes/` and `debug.log`, which satd never
creates, and those are gone.

The **Blockchain Sync** check showed `verificationprogress` as a percentage.
In 0.5.2 that field is the tip's timestamp over the current time, so a node at
genesis reported about 69%. The check now shows the block count against the
header count. The field itself is fixed separately.

The package's instructions now cover every action, its storage, its lack of
dependencies and its limitations, and it builds for `x86_64` and `aarch64`
only, matching the image, where the SDK's default would also attempt riscv.

## About this release

satd is free software under the [MIT License](../../LICENSE).

- **Stability & compatibility** — Tier 1 surfaces (Bitcoin Core-compatible
  JSON-RPC wire shape, CLI flag names/defaults, `bitcoin.conf` keys, on-disk
  layout, Electrum/Esplora surfaces) are governed by
  [`STABILITY_POLICY.md`](../../STABILITY_POLICY.md). satd follows
  [semantic versioning](https://semver.org/spec/v2.0.0.html); while in the
  `0.x` pre-1.0 line, deprecations may be accelerated (see the policy).
- **Security & disclosure** — report vulnerabilities per
  [`SECURITY.md`](../../SECURITY.md). Consensus-affecting bugs are treated as
  P0 with same-day acknowledgement.
- **Verifying this release** — tarballs are signed with minisign, container
  images with cosign (keyless OIDC), and git tags with SSH signatures (no GPG).
  The key matrix and verification steps are in
  [`SECURITY.md`](../../SECURITY.md).
- **Intentional differences from Bitcoin Core** — catalogued in
  [`CORE_DIFFERENCES.md`](../../CORE_DIFFERENCES.md).
- **Operating satd** — observability, the full flag matrix, tuning, and the
  downstream packaging contract live in the
  [Operator Manual](https://epochbtc.github.io/satd/).
