# satd 0.9.0

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.9.0 is in development. So far it adds an optional crawl mode, off by
default: with it off nothing changes.

## Highlights

- **Opt-in network crawl, `-crawl`.** Walks the reachable network as a
  declared crawler, over BIP 324 first and v1 after, and records which
  addresses complete a handshake. See [P2P](#p2p).

## P2P

- **Opt-in network crawl, `-crawl`.** With `-crawl=1` the node walks the
  reachable network: it seeds itself from the DNS seeds (`-dnsseed`
  respected; under a proxy the onion seeds, nothing looked up locally), the
  fixed seeds, a uniform sample of the address book, `-crawlseed` addresses
  and its own book, asks reachable nodes for addresses, dials what they
  name, and records the result in `crawlbook.dat` (at most 250,000
  addresses; the file holds peer addresses and is written with the data
  directory's permissions every 10 minutes and at shutdown).

  Each session is short and declares itself: protocol 70016, services 0,
  relay off, the node's real tip height, a fresh random nonce, a dummy
  `addr_from`, and the user agent `/satd:<version>(crawler)/`, with
  `-crawluacomment` as a second comment; then `wtxidrelay`, `sendaddrv2`
  and `verack`, and nothing else unsolicited. The node's own addresses
  and `-uacomment` never appear. BIP 324 is tried first; a node that
  refuses it as a v1-only node does (closing, or never answering, with
  nothing sent back) is redialled over v1, as Bitcoin Core does, and a node
  that did v2 is checked over v1 on first contact and weekly, so a node
  that only speaks v2 is told apart. A discovery session (first contact,
  then once a day, since Core caches its `getaddr` answer for about a day)
  sends one `getaddr`, waits up to 90 seconds for the answer, and with
  `-crawlprobes` (on by default) sends the survey's four probes, each
  checked against Bitcoin Core v32.1 for no misbehaviour score and no
  disconnect. A liveness session (every `-crawlliveness` seconds, 7200 by
  default and at least that, so at most 14 sessions a target a day) closes
  once the handshake settles. Unreachable addresses back off 1 h, 4 h,
  24 h, then daily.

  Limits, each with a ceiling no option lifts: `-crawlconcurrency` (32
  clearnet sessions, at most 256), `-crawltorconcurrency` (8, at most 256),
  `-crawlrate` (10 new sessions a second, at most 100), one session per
  address and two per IPv4 `/16` or IPv6 `/32`. At startup the crawl's
  sessions are fitted into the file-descriptor limit after
  `-maxconnections`: a limit too tight lowers the crawl's concurrency with
  a line in the log, never `-maxconnections`.

  The crawl is kept apart from the node: its connections are outside
  every connection budget and never in `getpeerinfo`,
  `getconnectioncount`, `getpeerbehavior`, eviction or the behaviour flags;
  nothing is relayed over them and a `getaddr` sent over one is answered
  with nothing. The address book is read to seed the crawl and never
  written: `peers.dat` is unchanged by a crawl. What the crawl learns is
  never relayed, served on `getaddr`, or given to the node's own dialer,
  the alt-slots or the extra-network peer. It dials what the node's dialer
  may (`-onlynet`, `-proxy`, `-onion`), narrowed by `-crawlnet`, and never
  clearnet through the proxy, so a Tor-only node crawls onions only; each
  onion dial has a Tor circuit of its own. I2P and CJDNS addresses are
  recorded, never dialled. `-crawlbind` sets the source address of direct
  dials, one per family. No session starts while the node is in initial
  block download, under `-connect`, or with networking off; a panic in a
  crawl task stops the crawl and leaves the node running. All options are
  read at startup only.

  With `-crawl=1` the network survey (`-peersurvey`) opens no connection:
  the crawl measures everything it would, from more addresses.
  `getpeersurvey` still reports the survey's store and says
  `"superseded_by_crawl": true`. `getconfig` reports the settings under
  `crawl`.

  **The crawl dials tens of thousands of addresses from this host's IP
  address** (or `-crawlbind`'s). Other operators' monitors will record it
  as a crawler, it may end up on ban lists that then refuse the node's own
  connections too, and hosting providers may receive abuse reports. The
  node logs this once at startup; a dedicated host is the better place to
  run it.

## Upgrade notes

No action required: the crawl is off by default.

## About this release

satd is free software under the [MIT License](../../LICENSE).

- **Stability & compatibility** — Tier 1 surfaces (Bitcoin Core-compatible
  JSON-RPC wire shape, CLI flag names/defaults, `bitcoin.conf` keys, on-disk
  layout, Electrum/Esplora surfaces) are governed by
  [`STABILITY_POLICY.md`](../../STABILITY_POLICY.md). satd follows
  [semantic versioning](https://semver.org/spec/v2.0.0.html): each feature
  release raises the minor version, and deprecations may be accelerated (see
  the policy).
- **Security & disclosure** — report vulnerabilities per
  [`SECURITY.md`](../../SECURITY.md). Consensus-affecting bugs are treated as
  P0 with same-day acknowledgement.
- **Verifying this release** — tarballs are signed with minisign, container
  images with cosign (keyless OIDC), and git tags with SSH signatures (no GPG).
  The key matrix and verification steps are in
  [`SECURITY.md`](../../SECURITY.md).
- **Intentional differences from Bitcoin Core** — catalogued in
  [`CORE_DIFFERENCES.md`](../../CORE_DIFFERENCES.md).
- **Operating satd** — observability, the full flag matrix, tuning, and the
  downstream packaging contract live in the
  [Operator Manual](https://epochbtc.github.io/satd/).
