# satd 0.7.0

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.7.0 is the next minor release on the 0.x line. Fixes for 0.6.0 ship as
0.6.x patch releases from the `release/0.6` branch.

This file accumulates entries as changes land; it is not yet a cut release.
Several mempool, relay, RPC and privacy defaults change to match Bitcoin Core;
read the [Upgrade notes](#upgrade-notes) before upgrading.

## Highlights

- **Bitcoin Core's ZMQ notifications**, byte for byte, so LND's `bitcoind`
  backend and Umbrel's apps run against satd unchanged
  ([details](#bitcoin-core-zmq-notifications)).
- **Package CPFP in `submitpackage`**, as in Core, so a Lightning commitment
  signed at a stale feerate can still be closed ([details](#mempool-policy)).
- **TRUC (version 3) transactions.** BIP 431's topology and size limits, with
  sibling eviction, as in Core ([details](#mempool-policy)).
- **OP_RETURN data pruning.** `-pruneopreturn=<N>` (off by default) strips
  large OP_RETURN payloads from deep blocks while txids and APIs keep working;
  `-restoreopreturns` undoes it ([details](#opreturn-data-pruning)).

## Bitcoin Core ZMQ notifications

satd now publishes Core's ZMQ topics; it used to ignore `-zmqpub*` with a
warning. `-zmqpubhashblock`, `-zmqpubhashtx`, `-zmqpubrawblock`,
`-zmqpubrawtx` and `-zmqpubsequence` take Core's syntax (multi-valued, one
socket per address, `unix:<path>` or `ipc://<path>`), `-zmqpub<topic>hwm` sets
the high-water mark (default 1000, 0 for none), and all ten options take
effect at restart. `getzmqnotifications`, `help`'s `== Zmq ==` category and
`-debug=zmq` behave as in Core.

Messages are Core's byte for byte, in Core's order within each event; a reorg
announces each block from the first with more work than the old tip, and
`invalidateblock` announces none. An unbindable address turns ZMQ off without
stopping the node; an invalid port stops startup with Core's message. Unlike
Core, satd promises no order between block-derived and mempool-derived
messages (per-topic sockets, as LND and Umbrel use, cannot tell), publishes
nothing for blocks connected during IBD or `-reindex`, drops a subscriber's
messages past 256 MiB queued, and lacks a few address forms; see the
[Operator Manual](https://epochbtc.github.io/satd/streaming.html#bitcoin-core-zmq-compatibility)
and `CORE_DIFFERENCES.md`. The streaming API remains the recommended
interface for new software.

A new PR-gating canary runs LND in `bitcoind` mode against satd's built-in
ZMTP 3.0 publisher; five of seven `interface_zmq.py` sub-tests pass.
`/metrics` gains six `satd_zmq_*` series. `-eventszmqbind` is unchanged.

## Streaming Consumption API

- **No events lost in a deep reorg.** The chain-event channel grows from 64
  to 1024 entries; a reorg of more than about 30 blocks could drop events.
- **A package's parent is announced before its child**, on the mempool stream
  and on ZMQ, for a zero-fee parent admitted with its child.

## Block validation

- **Tapscript signature hashes cost what they cost in Core.** The Rust engine
  (authoritative under `-consensus=rust` or `cpp-shadow`, shadow under
  the default `rust-shadow`) re-hashed the annex per signature check; it
  now follows Core's `SignatureHashSchnorr`. Results are unchanged.
- **A custom signet syncs past height 50,000**: a `-signetchallenge` signet no
  longer inherits the default signet's checkpoints or assumevalid block.
- **Contextual header rules on every path.** Timestamp (above MTP, at most two
  hours ahead) and BIP 34/66/65 version rules now also apply to `headers`
  messages and IBD blocks, before indexing, before storing and at connect, as
  Core's `AcceptBlockHeader`. A header refused only for being ahead of the
  clock no longer penalises its sender.
- **Transaction rules before a block is stored.** Context-free checks,
  `bad-txns-nonfinal` and `bad-cb-height` run before a block is written, as
  Core's `AcceptBlock`, so `submitblock` returns Core's reason instead of
  `inconclusive` and the header is marked invalid.
- **`-assumevalid` skips scripts only under Core's conditions** (ancestor of
  the assumevalid block on the best-header chain, minimum chain work met, two
  weeks of work deep), logging Core's "Enabling/Disabling script verification"
  lines. Off that branch satd verifies everything (stricter than Core).
- **`-minimumchainwork` takes effect** (it was ignored); a value Core refuses
  stops startup.
- **BIP 30 as Core checks it.** Skipped only above the BIP 34 height on a chain
  with the known BIP 34 block, and checked again from height 1,983,702.
  Testnet3 now checks every block; mainnet is unaffected until that height.
- **A failed `invalidateblock` leaves the node on a valid tip** (#977). It now
  disconnects to the invalidated block's parent first, as in Core.
- **A tall chain of low-work headers no longer puts the node in IBD** (#1119).
  The header height (`getblockchaininfo.headers`, the IBD check, readiness)
  is the most-work header's, as Core's `m_best_header`, not the highest
  header stored, so a minimum-difficulty fork taller than the real chain no
  longer stops transaction relay. The low-work headers are still stored
  until headers presync (#1132).

## Peers

- **A peer that sends an invalid block is disconnected** and banned, as Core's
  `MaybePunishNodeForBlock`, IBD blocks included; `noban` and manual peers are
  kept, local ones only disconnected. Compact-block reconstructions,
  future-timestamp refusals and blocks this node could not store are not
  charged (#544).
- **A peer stalling IBD is disconnected** (#972), as in Core, with a 15-second
  timeout that doubles per disconnect up to 64 seconds and returns to 15 as
  blocks connect. A peer counts as
  stalling only while another peer has delivered within the timeout, so a local
  link drop does not disconnect every peer; a peer silent for ten minutes is
  dropped regardless.
- **A node with a stale address book seeds itself** (#974), as in Core: DNS
  seeds if fewer than two full-relay outbound peers are up after 11 seconds (5
  minutes with 1,000+ addresses), and fixed seeds a minute later if the book
  still has nothing reachable.
- **A dial through `-proxy` gives the SOCKS5 exchange 20 seconds** (or
  `-timeout` if larger), as in Core; `-timeout` bounds only the connect to the
  proxy. `.onion` dials too.
- **An unroutable `-externalip` is not advertised**, as Core's `AddLocal`:
  private, loopback, 100.64.0.0/10, documentation and (unlike Core)
  `fc00::/8` addresses are left out of `addr`, `version` and
  `getnetworkinfo`'s `localaddresses`.

## Block relay

- **The tip is announced after a parallel-download catch-up**; peers relying
  on satd's announcements stayed behind.

## Privacy

- **`-onlynet` takes effect** (it was ignored) for automatic outbound
  connections and kept gossip addresses, as in Core; inbound and manual
  connections are unaffected. Startup refuses
  `-onlynet=onion` without `-proxy` or `-onion` (unlike Core, `-listenonion`
  alone is not enough) or with `-onion=0`, `-onlynet=cjdns` without
  `-cjdnsreachable`, `-onlynet=i2p` (no I2P transport) and unknown networks.
  DNS seeding is off when IPv4 and IPv6 are excluded, and `-dnsseed=1` with
  such an `-onlynet` is refused.
- **`-proxy` turns listening off by default**, as in Core. `-bind` or
  `-listen=1` keeps it; `-listen=0` also disables `-listenonion` unless set.
- **`-proxy=0` and `-onion=0` mean "none"**, as in Core (`-onion=0` blocks
  `.onion` even for manual peers); satd used `0` as an address.
- **Under `-proxy`, DNS seeds are resolved by the proxy** (#994) over
  short-lived `addr-fetch` connections, as in Core; nothing goes to the local
  resolver and the startup warning is gone. `-seednode` host names are opened
  the same way (not under `-connect`), and `getpeerinfo` shows them by name
  with `network` `not_publicly_routable`. Host names in `-addnode` and
  `-connect` are still refused under `-proxy`.
- **The onion address survives a restart** (#973): the key is kept in
  `onion_v3_private_key` in the network's data directory, as in Core. An
  upgrading node gets one last new address.
- **The hidden service comes back after Tor restarts** (#973): the address is
  withdrawn while the control connection is down, and satd reconnects (backoff
  up to 10 minutes; unlike Core, also after authentication or `ADD_ONION`
  failures) and re-adds it with the same key. **`-externalip` takes a v3 onion
  address** (#973), advertised while the node has no service of its own up.
- **Files satd creates are readable by its own user only** (`umask(077)`):
  new directories 0700, new files 0600; the RPC cookie follows
  `-rpccookieperms`. Existing files keep their modes until rewritten.
- **v2 (BIP 324) handshakes send 0 to 4095 random garbage bytes**, as Core
  does; fixed sizes made satd's connections identifiable.

## Health and readiness

- **Unknown soft forks are reported** (#976), as Core does: a locked-in bit is
  logged, and an active one adds "Unknown new rules activated (versionbit N)"
  to the `warnings` of `getblockchaininfo`, `getmininginfo` and
  `getnetworkinfo` and fires `-alertnotify`.
- **`/readyz` notices a node that has lost its peers** (#979): it is 503,
  naming the detector, while `tip_stall` (`-alerttipstallseconds`, default one
  hour) or `peer_floor` (`-alertpeerfloor`, default three, held a minute) is
  raised. Both are `0` on regtest; `0` excludes a detector.
- **`-alertnotify` runs for warnings raised during startup** (#884), such as
  `reindex.halted` and `reindex.short`.

## Address relay

- **`getaddr` is answered as Core answers it**: inbound peers only, once per
  connection, from a per-listener sample of at most 23% of the address book
  (at most 1,000) cached about a day; `addr`-permission peers get a fresh one.
  `-externalip` addresses are announced to outbound peers at connect instead.
- **Address service bits follow the peer's `version`**, as in Core.
- **One network group can no longer fill the tried table.** Tried entries use
  Core's bucket/position slots (at most 8 of 256 buckets per group) with
  test-before-evict, and tried dials pick a bucket first. `addpeeraddress …
  true` into a taken slot answers `failed-adding-to-tried`. The placement key
  is appended to `peers.dat` (0.6.x still loads it); an existing file is
  re-placed under a fresh key, trimming each group to its share.
  `getrawaddrman` reports each entry's slot.
- **One peer can no longer fill the onion candidate list** (512, in memory):
  at most 64 per source, and a full list evicts an entry terrible by Core's
  `IsTerrible`.
- **Outbound peers are asked for addresses, and dials spread over the book**,
  as in Core: `getaddr` to every address-relaying outbound peer, seed
  addresses added to the book as new, dials drawn at random from tried or new,
  and addresses dialled in the last ten minutes skipped.

## Block serving

- **A pruned node no longer claims to be a full node.** Pruned nodes and nodes
  behind an AssumeUTXO snapshot advertise `NODE_NETWORK_LIMITED` without
  `NODE_NETWORK`; every node sets `NODE_NETWORK_LIMITED`, so an unpruned node
  reports `localservices` `0000000000000409` (plus `NODE_P2P_V2` and
  `NODE_COMPACT_FILTERS` when on).
- **Blocks are served as Core serves them** (`BlockRequestAllowed`): off-chain
  blocks only if validated and within 30 days of the best header. A pruned node
  disconnects a non-`noban` peer asking for a block more than 290 below its
  tip, and `getblocks` stops 282 below the tip.
- **Old blocks from limited peers that still hold them.** A
  `NODE_NETWORK_LIMITED` peer that also advertises `NODE_INTACT_BLOCKS` (bit
  28, `INTACT_BLOCKS` in `getpeerinfo`) serves every intact block and answers
  `notfound` for the rest. satd now fetches old blocks from such peers (for
  peer-less `getblockfrompeer`, only without a `NODE_NETWORK` peer) but never
  seeks them out.

## OP_RETURN data pruning

`-pruneopreturn=<N>` (off by default; minimum 288, `1` or `all` mean 288)
starts a worker that, below `tip − N − 2`, zeroes the payload of each
non-coinbase OP_RETURN output of at least `-pruneopreturnsize` bytes (default
4096; `k`/`M` and `KiB`/`MiB` suffixes accepted) and punches it out of the
block file (`fallocate(PUNCH_HOLE)` on Linux, `F_PUNCHHOLE` on macOS). Txids
and a hash of the zeroed block are stored first, so `-reindex`,
`-reindex-chainstate` and every surface keep real txids; blocks are still
fully validated. The worker pauses during IBD, reindex and AssumeUTXO
background validation, and startup fails if the filesystem cannot punch
holes. Only whole filesystem blocks are freed, so today's chain gives back
little (a 100 KB output frees about 96 KB). It is not a secure erase: copies,
snapshots, backups and the last 288 blocks keep the bytes.

A stripping node gives up:

- **Archive-peer status.** It advertises `NODE_NETWORK_LIMITED`, not
  `NODE_NETWORK`, while any block is stripped, option on or off.
  `-pruneopreturnpeers=limited` (default) serves the last 288 blocks;
  `=intact` also serves intact blocks at any depth, advertises
  `NODE_INTACT_BLOCKS` and answers `notfound` for stripped ones.
- **Raw bytes of stripped transactions.** `getblock` verbosity 0 returns
  `Block not available (pruned data)`; `getrawtransaction` hex, Esplora `/raw`
  and `/hex`, and non-verbose Electrum `blockchain.transaction.get` refuse
  (`Transaction data not available (OP_RETURN data stripped)` over RPC). JSON
  views mark the transaction `opreturn_stripped` and show each stripped script
  as bare `OP_RETURN` with its original size. Streaming rescan events
  (`ScriptMatched`, `PrefixMatched`, `SilentPaymentMatched`) carry
  `raw_tx_stripped` instead of `raw_tx`; `PrefixMatched` now always carries
  `txid`.
- **Deep reorgs.** A reorg or `invalidateblock` that would disconnect a
  stripped block fails, naming it, and changes nothing.
- **Script re-verification on `-reindex`** for stripped transactions' inputs.

`getopreturnpruneinfo` reports configuration, worker state, progress and
totals, also under `getblockchaininfo`'s `opreturn_prune`; Prometheus gets
`satd_opreturn_*` metrics and sat-tui `op-prune` and `op-restore` columns.
`getblockfrompeer` restores one block in place (re-stripped on the next pass
if the option is on). With the option off, restoring the last stripped block
makes the node a full node again without a restart and removes the strip
column family.

**`-restoreopreturns`**, with every `-pruneopreturn*` option removed (it is
refused alongside them), re-downloads all stripped blocks and writes them back
in place, resuming after a restart. It asks only connected `NODE_NETWORK` +
`NODE_WITNESS` peers (16 blocks per peer, 1024 in flight, 15-second timeout,
no re-ask after `notfound`), restores newest first on a pruning node, and waits
while the tip is behind, no full peer is connected, or the blocks volume lacks
the room needed plus 1 GiB. When it finishes the node advertises
`NODE_NETWORK` again and the log says the option can be removed. Progress and
ETA appear under `getopreturnpruneinfo`'s `restore` and in
`satd_opreturn_restore_*` metrics.

The Rust and Go event clients mark a stripped prefix hit
`outputs_unavailable` / `OutputsUnavailable` (reported by `has_unresolved` /
`HasUnresolved`); their new public struct fields break Rust code that builds
them with literals. See
the [Operator Manual](https://epochbtc.github.io/satd/disk-footprint.html#opreturn-data-pruning).

## Mempool policy

- **`submitpackage` does package CPFP** (#984), as Core's `AcceptPackage`: a
  member refused alone only for feerate is judged with its paying child by
  combined feerate (shared `effective-feerate`, `effective-includes`); a short
  package is refused on the child with `min relay fee not met` or
  `mempool min fee not met`. The pool is trimmed after the whole package is in
  (a trimmed member reports `mempool full`), eviction ranks by descendant
  score, and an ephemeral dust parent's child now pays for both.
- **TRUC (BIP 431) for version 3 transactions** (#1020), as Core: at most one
  unconfirmed parent and one child, at most 10,000 vbytes (1,000 with an
  unconfirmed parent), only v3 may spend unconfirmed v3, always replaceable. A
  second child may evict the first (refusal
  `insufficient fee (including sibling eviction)`); other violations are
  `TRUC-violation`, in `package_msg` within a package. Reorg-returned
  transactions are exempt; `mempool.dat` reloads are not. Replacement checks
  now follow the fee floor, so a replacement below it is refused for its fee.
- **Cluster limits**: Core v31's `-limitclustercount` (default and maximum 64)
  and `-limitclustersize` (default 101 kvB, sigop-adjusted; was an unknown
  option) bound the whole connected cluster, refusing as `too-large-cluster`
  (satd counted only ancestors). The size also sets the `-maxmempool` floor
  (40 clusters). After a reorg, oversized clusters are trimmed as Core's
  `TxGraph::Trim`, reported as `reorg` evictions.
- **Replacements are judged by full cluster feerate diagrams**, as Core v31.
  Some bumps Core accepts now pass; some satd accepted, such as evicting a
  well-paying child, are refused. satd linearizes greedily, so large clusters
  can differ from Core at the margin (see
  [`CORE_DIFFERENCES.md`](../../CORE_DIFFERENCES.md)).
- **Package RBF**, as Core v31: a parent and child with no in-mempool parents
  can replace together if they pay the evicted fees plus their own relay, beat
  the parent's feerate, conflict with at most 100 clusters and improve the
  diagram. Refusals go in `package_msg` (`package RBF failed: …`); nothing is
  evicted until both are fully checked.
- **Multi-transaction `testmempoolaccept` is a package evaluation**, as Core's
  `AcceptMultipleTransactions`: transactions may spend earlier ones, replacing
  mempool transactions is `bip125-replacement-disallowed`, set-wide TRUC or
  cluster violations are each one's `package-error`, a child must spend its
  parents' ephemeral dust, and the first refusal stops evaluation. Feerates
  are still per transaction. `txn-already-known` now carries `reject-details`.
- **Core's script policy.** The mempool runs Core's `PolicyScriptChecks`
  (`STANDARD_SCRIPT_VERIFY_FLAGS`, Rust engine, any `-consensus`) and refuses
  spends of soft-fork upgrade hooks, non-standard signatures and pushes,
  unrecognised output types, P2SH with more than 15 sigops, inputs over BIP
  54's 2500 legacy sigops, bloated witnesses, and sigop cost above 16000, with
  Core's reasons (`mempool-script-verify-flag-failed (...)`,
  `bad-txns-nonstandard-inputs`, `bad-witness-nonstandard`,
  `bad-txns-too-many-sigops`), on `mempool.dat` reload too.
  `-acceptnonstdtxn` lifts only the input checks; relaying peers are not
  penalised.
- **`-bytespersigop` takes effect** (default 20; was ignored): mempool
  feerates, reported `vsize` and template ranking use Core's sigop-adjusted
  size. `weight` is unchanged.
- **Ephemeral dust package parents** are checked for output standardness and
  by the transaction policy (`policyfile=`): a local one the rules would
  quarantine is refused, a peer's is held with its child, and one spending
  another package member is refused if it carries a `prioritisetransaction`
  delta, as Core's `PreCheckEphemeralTx`. Their entry time follows the node
  clock (#981).
- **`prioritisetransaction` deltas for absent transactions survive a restart**
  (#981) in `mempool.dat`; the file version is unchanged and older satd
  ignores them.

## Transaction relay

- **A parent and its child are relayed together** (Core's opportunistic
  1-parent-1-child relay): a fee-refused parent from a peer is retried with a
  child the same peer sent, judged as `submitpackage` judges it. A failed pair
  is not retried before the next block.
- **Every peer announcing an orphan is recorded and asked for its parents.**
- **The orphanage is limited as Core v30's is**, replacing the 100-orphan,
  50-per-peer, 20-minute limits: a latency-score limit of 3,000 and 404,000 WU
  per announcing peer, enforced by evicting the highest-DoS-score peer's
  announcements. Orphans no longer expire and are keyed by wtxid, so a
  malleated copy cannot block the real one; `getorphantxs` lists in wtxid order.
- **Transactions are announced on Core's schedule**, from per-peer queues on
  Poisson timers averaging 2 seconds outbound and 5 inbound, at most 70 per
  `inv` (up to 1000 for long queues); `noban` peers are not delayed. A request
  for an unannounced transaction gets `notfound`, except one from the most
  recent block or returned by a reorg, and a BIP 35 `mempool` request is
  answered with the peer's next announcement. New `txannouncedelay=0`
  (satd extension, reloadable) announces at once, giving up that privacy.
  `getpeerinfo`'s `inv_to_send` and `last_inv_sequence` are now filled in.
- **An announced transaction is downloaded once**, as Core's
  `TxRequestTracker`: one request in flight per transaction, outbound peers
  preferred, inbound and txid announcements delayed 2 seconds, 60-second
  timeout, at most 5000 tracked announcements per peer without the `relay`
  permission. Waits follow `setmocktime`.
- **A refused transaction is not fetched again.** The last 120000 refusals
  are remembered by wtxid until the tip moves, as in Core; fee-only refusals
  go to a separate filter so a paying child can still bring them in.

Core functional tests that now pass against satd: `mempool_limit.py`,
`mempool_truc.py`, `mempool_package_limits.py`, `mempool_package_rbf.py`,
`p2p_opportunistic_1p1c.py`, `mempool_reorg.py`, `p2p_leak_tx.py`,
`rpc_orphans.py`, `p2p_1p1c_network.py` and
`rpc_signmessagewithprivkey.py`.

## RPC

- **`gettxoutsetinfo` refuses the arguments it cannot honour** (#896) instead
  of ignoring them: a `hash_or_height` other than the tip fails with Core's
  no-coinstatsindex error (-8), and `hash_type` `muhash` or
  `hash_serialized_3` fails by name (-8).
- **`verifybip322`** (satd's own) verifies BIP 322 signatures (`smp`, `ful` or
  unprefixed) for any address type, answering `valid`, `inconclusive` or
  `invalid`; `pof` is unsupported. Its legacy/P2SH MINIMALIF flag cannot be
  set by block or mempool validation.
- **`verifymessage` and `signmessagewithprivkey`**, Core's legacy P2PKH message
  signing, byte-compatible with Core.
- **`getorphantxs`** (Core's hidden RPC, verbosity 0–2).
- **`getorphaninfo`** adds `announcements`, `latency_score`,
  `max_latency_score`, `weight` and `max_weight`; `max_size` now holds the
  latency limit.
- **`getblock` and `getrawtransaction` answer as Core v31's do** (#978):
  `getblock` adds `strippedsize` and `coinbase_tx`; `getblock` verbosity 2
  adds each transaction's `fee` and verbosity 3 each input's `prevout`, and
  `getrawtransaction` verbosity 2 its `fee` and `prevout`, all read from undo
  data so no `-txindex` is needed; a coinbase input shows `txinwitness`.
  Fields Core lacks are removed (see Upgrade notes).
- **`gettxspendingprevout`**, as Core v31, served from the address index's
  spend rows. `-txospenderindex` (previously ignored) enables block lookups,
  requires `-addressindex` and is refused with pruning. Unlike Core, a spender
  in a block removed by `invalidateblock` disappears at once.
- **`getrawmempool` lists in Core's mining order** (best chunks first),
  matching Core wherever satd linearizes the same way; it was hash-map order.
  Verbose keys stay sorted by txid.
- **`gettxout`'s `scriptPubKey` adds `desc`, `address` and `type`**, and
  **`type` follows Core's `Solver`** everywhere (`pubkey`, `multisig`,
  `anchor`, `witness_unknown` instead of `nonstandard`; `nulldata` only for
  push-only scripts).

## Node attestation

satd can publish and collect Node Attestation Protocol (NAP) attestations:
non-binding statements signed by Bitcoin holders, one key-value pair per coin,
weighted by the coin's value while it stays unspent. The manual's
[Node Attestation](https://epochbtc.github.io/satd/nap.html) chapter covers
signing with each kind of wallet, the privacy costs and the statuses.

- **`-nap=1`** (off by default) publishes. The store is
  `<datadir>/nap/attestations.dat` plus an append-only
  `attestations.journal`; an unreadable store stops startup unless
  `-napstorerecover=1`, which renames both with a `.bad-<unix time>` suffix
  and starts empty. `-napmaxattestations=<n>` caps it (default no limit;
  `store-full` at the cap).
- **`createnapattestation "<txid>:<vout>" "key" "value" ( "descriptor" )`**
  returns the text and a BIP 322 `to_sign` PSBT, anchored 6 blocks below the
  tip, for a coin of at least 10,000 sats and 4,032 blocks of age (6 on test
  networks; coinbase coins wait for maturity).
- **`submitnapattestation "message" "signature"`** takes BIP 322 signatures,
  legacy `signmessage` for P2PKH, a signed `to_sign` transaction or a signed
  PSBT. Refusals are -26 naming the rule (`stale`, `coin-too-small`, …). One
  attestation per coin and key, at most 32 keys per coin.
  **`listnapattestations`** and **`removenapattestation`** manage them.
- **Serving.** A publisher advertises `NODE_NAP` (bit 30, `NAP` in
  `getnetworkinfo`) and answers `getnapatt` in 1 MB pages: one pull per
  connection per 10 minutes, 200 MB an hour (eight times that per network
  group); over-limit requests are ignored, malformed ones are misbehaviour. It
  never sends NAP messages unasked, so Core peers are unaffected. Stale
  attestations and ones whose anchor a reorg removed are kept but not served.
- **Aggregating.** `-napaggregator=1` (off by default, independent of `-nap`)
  pulls from `NODE_NAP` peers at connect and hourly, and over new short
  `nap-pull` connections that take no outbound slot, with budgeted
  verification (5,000 per pull, 1,000,000 an hour). It keeps at most 256 keys
  per coin and `-napaggregatormax` attestations (default 1,000,000) in
  `<datadir>/nap/aggregate/aggregate.dat`; **`listnapaggregate`** lists them.
- **Reports.** **`getnapreport`** (`rpc:read`) gives each key's weight per
  value, in integers. **`exportnapsnapshot`** and **`replaynapsnapshot`**
  (`rpc:write`) let any node reproduce a published report byte for byte.

## Electrum and Esplora

- **Electrum subscription caps fit a desktop wallet.**
  `-electrummaxsubsperconn` defaults to **10,000** (was 1000) and the shared
  `-addrindexsubscriptions` registry to **50,000** (about 230 MB when full);
  explicit values are kept. Subscribing no longer sweeps the registry each
  time.
- **A backfilled address index leaves out unspendable outputs**, as a live one
  does; rows from an earlier backfill need no action.
- **A scripthash's history is capped by the work it costs.** Electrum
  `get_history`, `get_balance`, `listunspent` and `subscribe`, and Esplora
  address and scripthash stats, `/utxo` and `/sse`, stop reading at the cap
  instead of loading the whole history. Electrum answers code `2`,
  `history too large (cap = 200000 entries)`; a refused `subscribe` is not
  kept, and a subscription that grows past the cap stops notifying. Esplora
  answers 400 `Too many history entries (more than 200000 transactions)`.
  As-of answers built from history are under the same cap; `get_first_use`
  and paged `/txs` routes are not. New `-addrindexmaxhistory=<n>` (default
  200000; `0` for no cap) sets it.
- **Esplora responses name their chain tip** in `X-Bitcoin-Chain-Tip` and
  `X-Bitcoin-Chain-Tip-Height` (mempool/mempool#6584, as rbitcoin serves).
  Each request answers for the tip it started at and is rerun after a
  disconnect; eight in a row answer 503 `chain view moved`. Mempool and fee
  routes, `POST /tx`, `/txs/mempool` and SSE carry no headers; `-esploracors`
  exposes them.
- **Esplora `?asof=<blockhash>`**, with rbitcoin's rules, answers address,
  scripthash, `/txs`, `/utxo`, tx status and outspend routes as of a block on
  the best chain, without the mempool. A hash not on the best chain, a
  malformed `asof`, or `asof` on another route is 404.
- **Electrum answers name their chain tip** in `chain_tip` and
  `chain_tip_height` beside `result` on `blockchain.scripthash.get_history`,
  `get_balance`, `listunspent` and `blockchain.transaction.get`, `get_merkle`,
  `id_from_pos`, as rbitcoin does (`server.features`: `"chain_tip": true`),
  with the same rerun rule (error `chain view moved`). `server.version`
  accepts and echoes rbitcoin's `1.4.2-asof`; the protocol is still 1.4.
- **Electrum trailing `asof:<blockhash>`** (rbitcoin's argument) on the same
  six methods answers as of that block without the mempool; a hash off the
  best chain is `asof not on chain`. satd does not require `1.4.2-asof`
  negotiation; `server.features` reports `"asof": true` and
  `"asof_protocol": "1.4.2-asof"`. **Clients must check `asof` there first**:
  older servers may read `asof:…` on `transaction.get`, `get_merkle` or
  `id_from_pos` as a `false` flag and answer live.

## Shutdown

- **Shutdown waits for running RPC calls** (#983), as Core's `Shutdown()`, for
  a quarter of the remaining `-maxshutdownsecs`; a call still running costs the
  clean-shutdown marker, not the flush. `generatetoaddress` and
  `generatetodescriptor` return the blocks mined so far, the `waitfor*` calls
  return the current tip, and a long-polling `getblocktemplate` fails with
  `-9 "Shutting down"`.

## Mining

- **`getblocktemplate`'s `mintime` and `curtime` take the BIP 94 retarget
  floor on every network**, as Core's `GetMinimumTime`; on testnet4 a block at
  the advertised `mintime` could fail as a timewarp. Stratum shares and Job
  Declaration jobs below the floor are refused.
- **`getblocktemplate` on mainnet waits for peers and IBD**, with Core's
  `RPC_CLIENT_NOT_CONNECTED` (-9) and `RPC_CLIENT_IN_INITIAL_DOWNLOAD` (-10).
  Test chains and proposal mode are not gated.

## Configuration

- **List options take both sources** (#995). Core's list options (`bind`,
  `whitebind`, `connect`, `addnode`, `seednode`, `rpcbind`, `rpcallowip`,
  `rpcauth`, `whitelist`, `externalip`, `onlynet`, `signetseednode`,
  `signetchallenge`, `debug`, `debugexclude`, `loglevel`) now merge the command
  line and `bitcoin.conf`, command line first, as in Core; a trailing negation
  (`-noconnect`) still drops the file's values. satd's own list options are
  unchanged.
- **The `getaddr` answer cache follows `setmocktime`.**
- **`-maxmempool` below 5 MB is refused** with Core's
  `-maxmempool must be at least 5 MB`; `0` is still allowed.

## Terminal dashboard

- **A NAP view on key `5`** when `-nap` or `-napaggregator` is on: published
  attestations and the `getnapreport` breakdowns.
- **The services row is yellow wherever work is pending** (backfills,
  restores); green means done or serving.
- **The mempool view (`3`) has a Quarantine panel** while a policy is loaded
  (held transactions against the `quarantinemempool` budget, foregone fees, a
  per-rule table); the steady view's Txs line adds the held count.

## TLS clients

- **`-rpccacert` replaces the public roots instead of adding to them** in
  `sat-cli` and `sat-tui`, so a mis-issued public certificate for the node's
  hostname can no longer receive RPC credentials. Without `-rpccacert` the
  public roots still apply. Also shipped in 0.6.3.

## Dependencies

- `rustls-webpki` 0.103.16 (RUSTSEC-2026-0382), `webpki-roots` and
  `webpki-root-certs` 1.0.10 (RUSTSEC-2026-0381, -0383), as in 0.6.2, for the
  distrusted emSign intermediates.
- `zstd-sys` 2.1.2 (RUSTSEC-2026-0410); the advisory is wasm32-only and no
  satd build was affected.

## Upgrade notes

- **`gettxoutsetinfo` with a historical `hash_or_height`, or with
  `hash_type` `muhash` or `hash_serialized_3`, now fails** with -8 (see
  RPC). It used to answer with the tip's stats. Call it with no arguments,
  or with `hash_type` `"none"`, to get the tip's.

- **`-rpccacert` is now the only trust anchor** for `sat-cli` and
  `sat-tui` (see TLS clients). An invocation that names a private CA but
  connects to a node whose certificate a public CA issued now fails the
  handshake. Drop `-rpccacert` for such a node, or point it at the public
  CA's root or intermediate.

- **Transactions reach peers a few seconds later** (see Transaction
  relay): 2 seconds on average for outbound peers and 5 for inbound, as in
  Core. Tooling that expects a transaction on a peer the instant it enters
  this node's mempool should wait for it, give the peer `noban`, or set
  `txannouncedelay=0`.

- **The mempool bounds each transaction's whole cluster** (see Mempool
  policy). A transaction joining a cluster of 64 is refused as
  `too-large-cluster`, however its relatives are arranged; before, only its
  ancestors counted. Software that hangs many children off one unconfirmed
  parent (a batch payout spending its own change) sees the 64th refused, as
  on Core v31.
- **Some replacements satd used to accept are now refused** (see Mempool
  policy, "Replacements in larger clusters"). A replacement that evicts a
  conflict's high-feerate descendants must now improve the whole cluster,
  as on Core v31. The cluster order satd uses is an approximation of
  Core's, so on large clusters the two can differ at the margin.
- **`getblock`, `getrawtransaction` and `decoderawtransaction` drop the
  fields Core does not have** (see RPC). Software reading them must change:
  - `getrawtransaction` no longer has `blockheight`; read the height from
    `getblockheader <blockhash>`.
  - A mempool transaction no longer has `"confirmations": 0`: the field
    is absent, as in Core.
  - At verbosity 2, a mempool transaction has no `fee` or `prevout`, as in
    Core; `getmempoolentry` has its fees.
  - Transactions inside `getblock` no longer carry `blockhash`,
    `blockheight`, `confirmations`, `time` or `blocktime`.
  - `decoderawtransaction` no longer echoes the transaction's `hex`.

- **A node with `-proxy` and no explicit `-listen` stops accepting inbound
  connections**, and without an explicit `-listenonion` it stops publishing
  its hidden service. To keep either, set `listen=1` (and `listenonion=1`).
- **Configs with `-onlynet` may now refuse to start**, with Core's message,
  where they combine options Core refuses (see Privacy).
- **A `-maxmempool` between 1 and 4 now stops the node from starting** (see
  Configuration). Raise it to at least 5.
- **Sigop-dense transactions cost more to relay.** A transaction whose sigop
  cost times 20 exceeds its weight now needs a fee for that larger size, and
  its reported `vsize` grows to match.
- **The mempool refuses non-standard scripts.** A transaction Core's
  mempool would refuse for its scripts or what it spends is now refused by
  satd's, including one loaded from an existing `mempool.dat`. Send such
  spends to a miner directly.
- **A pruned node advertises `NODE_NETWORK_LIMITED` instead of
  `NODE_NETWORK`.** Peers that need the whole chain stop syncing from it, and
  a peer asking it for a block more than 290 below its tip is disconnected.
- **A list option set in both `bitcoin.conf` and on the command line now
  takes both** (see Configuration). Check a command line that repeats a
  `bind`, `rpcbind`, `connect` or `addnode` from the config file: the node now
  gets the union, and a duplicate `bind` or `whitebind` stops startup.
- **New files in the data directory are 0600, and new directories 0700**,
  as in Core (see Privacy). If another account reads satd's files, grant it
  access explicitly. For the RPC cookie, use `-rpccookieperms=group` or
  `all`.
- **Electrum and Esplora refuse scripthashes with more than 200,000
  transactions** for requests whose cost follows the whole history (see
  Electrum and Esplora): Electrum `get_balance`, `listunspent` and
  `subscribe` (as `get_history` already did), Esplora address stats, `/utxo`
  and `/sse`. Esplora's `/txs/chain` pages still serve such a history, and
  `-addrindexmaxhistory` raises or removes the cap.
- **`-zmqpub*` options now take effect.** `zmqpub*` lines carried over from
  Bitcoin Core, ignored with a warning before, now bind at startup. If a Core
  node on the same machine still holds an address, satd logs the bind failure
  and runs with ZMQ off, as Core would; remove the lines if you do not want
  satd publishing.
- **A datadir that has used `-pruneopreturn` cannot be opened by satd
  0.6.x or earlier** (RocksDB reports `Column families not opened:
  opreturn_strip`). This is deliberate: older versions would misread the
  zeroed data. Turning the option off restores nothing; `-restoreopreturns`
  downloads the stripped blocks again, and `getblockfrompeer` brings back
  one.
