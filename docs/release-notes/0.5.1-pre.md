# satd 0.5.1

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.5.1 is a patch release on the 0.5.x line. Planned scope: the regtest
halving-interval divergence from Bitcoin Core (#608) and spending the
untweaked-P2TR output shape — the BIP 352 silent-payment form — through
`signrawtransactionwithkey` (#609).

This file accumulates entries as changes land; it is not yet a cut release.

## Highlights

- Silent-payment outputs can now be spent through the node's own signing paths:
  `signrawtransactionwithkey` and `sat-cli`'s PSBT signer handle untweaked P2TR
  key-path spends the way Bitcoin Core does (#609).

## Fixed

### Spending silent-payment outputs through the node's own signing paths (#609)

A BIP 352 silent-payment output is a P2TR output whose key **is** the derived key,
with no taptweak applied. Both of satd's signers — the `signrawtransactionwithkey`
RPC and `sat-cli`'s local PSBT signer — assumed every P2TR key-path spend was the
BIP 341/86 shape and unconditionally applied the taptweak, so a wallet backend
that located its silent-payment outputs through satd's tweak index was then told
`"Unable to sign input, no matching key"` when it handed the node the exact
private key that controls them.

Both signers now mirror Bitcoin Core's two-attempt key-path signing: each key is
first tried as a BIP 341/86 internal key (taptweak applied), and if no key
matches, tried directly against the output key with no tweak. The tweaked
reading is attempted first, so existing BIP 86 spends are unchanged.
