# satd 0.5.1

> Pre-release — in progress · [Changelog](../../CHANGELOG.md)

satd 0.5.1 is a patch release on the 0.5.x line. Planned scope: the regtest
halving-interval divergence from Bitcoin Core (#608) and spending the
untweaked-P2TR output shape — the BIP 352 silent-payment form — through
`signrawtransactionwithkey` (#609).

This file accumulates entries as changes land; it is not yet a cut release.

## Highlights

- Silent-payment outputs can now be spent through the node's own signing paths:
  `signrawtransactionwithkey` and `sat-cli`'s PSBT signer handle untweaked P2TR
  key-path spends the way Bitcoin Core does (#609).
- A batch of Bitcoin Core parity fixes: the regtest halving interval (#608),
  `-testactivationheight` support, the `bad-blk-length` / `bad-blk-weight`
  reject-reason split, an always-present `default_witness_commitment` (#548),
  and a consistency fix for `gettxoutsetinfo` (#556).

## Fixed

### Spending silent-payment outputs through the node's own signing paths (#609)

A BIP 352 silent-payment output is a P2TR output whose key **is** the derived key,
with no taptweak applied. Both of satd's signers — the `signrawtransactionwithkey`
RPC and `sat-cli`'s local PSBT signer — assumed every P2TR key-path spend was the
BIP 341/86 shape and unconditionally applied the taptweak, so a wallet backend
that located its silent-payment outputs through satd's tweak index was then told
`"Unable to sign input, no matching key"` when it handed the node the exact
private key that controls them.

Both signers now mirror Bitcoin Core's two-attempt key-path signing: each key is
first tried as a BIP 341/86 internal key (taptweak applied), and if no key
matches, tried directly against the output key with no tweak. The tweaked
reading is attempted first, so existing BIP 86 spends are unchanged.

### Regtest block subsidy halves at Core's interval (#608)

The halving interval was a network-blind 210,000; Core's
`nSubsidyHalvingInterval` is 150 on regtest. From height 150 a regtest satd
accepted coinbases Core rejects (and its own `getblocktemplate` overpaid).
`block_subsidy` is now network-aware; no other network changes.

### Core-compat gaps from the #541 review (#548)

Three independent parity fixes, each small:

- **`-testactivationheight=name@height` is implemented** rather than
  warn-and-ignored. Core's syntax and semantics: regtest-only (any other chain
  refuses to start), repeatable, names `bip34` / `dersig` / `cltv` / `csv` /
  `segwit`, last value wins per name, single-dash spelling accepted. Moving
  `segwit` up drags `taproot` with it so the script-flag set stays coherent
  (a taproot spend is a witness spend). This unlocks the Core functional-test
  shapes that relocate buried deployments.
- **Over-weight blocks now reject `bad-blk-weight`**, computed after the
  witness rules exactly as Core orders `ContextualCheckBlock`, with
  `bad-blk-length` reserved for `CheckBlock`'s stripped-size test. Verdicts
  are unchanged — only the reject reason and its position moved — but the
  live block-acceptance differential compares reasons, and the previously
  conflated label diverged for over-weight blocks inflated by witness data.
- **`getblocktemplate` emits `default_witness_commitment` on every
  post-segwit template**, witness transactions or not, as Core does; it is
  omitted entirely below an overridden segwit height (Core's `fPreSegWit`).
  Previously a witness-free template carried an empty string, pushing
  external mining software toward computing its own commitment — newly
  hazardous since #541 made a wrong coinbase witness nonce a hard rejection.

### `gettxoutsetinfo` reads one consistent view (#556)

The RPC read its tip, coin count, total amount and height histogram as
independent lookups; a block connecting mid-call could pair a tip at height
H with totals from H+1, breaking the documented "histogram sums to `txouts`"
invariant and mis-stating the total by a block's subsidy and fees. All five
fields are now read under the chain's accept lock after the coin-cache
flush, so they always describe the same height. Same shape as the backfill
cursor fix in 0.5.0 (#549/#554), applied to the UTXO-set statistics.
